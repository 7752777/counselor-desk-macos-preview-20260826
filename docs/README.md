## 文档使用约定

- 所有示例、截图、Issue 和讨论都只能使用虚构或脱敏数据。
- 下载文件、平台支持、哈希与签名状态以 Release 页面实际内容为准。
- 文档只记录已经验证的事实；当前维护发布线为 v4.8.5，仓库已私有，附件、哈希和签名状态以实际权限可见的 [v4.8.5 发布收尾记录](./upgrade/release-v4.8.5.md)和 GitHub Release 为准；v4.8.3、v4.8.2、v4.8.1、v4.8.0 及更早版本仅作为历史兼容基线保留。
- 开发目录的当前功能、测试和已知限制以[开发说明](./development.md)、[当前全量状态与后续提升路线](./upgrade/comprehensive-status-and-roadmap-2026-08-22.md)、[AI 全面审计](./upgrade/ai-comprehensive-audit-2026-08-19.md)和[v4.8.5 发布收尾记录](./upgrade/release-v4.8.5.md)为准；`codex/ai-upgrade` 是维护分支，不替代正式 Release。

以下几段保留为发布前审计历史，用于解释 v4.8.0/v4.8.1/v4.8.2/v4.8.3 的修复过程；当前正式状态以本文件顶部入口和[v4.8.5 发布收尾记录](./upgrade/release-v4.8.5.md)为准。

### 发布前审计更正：二维码已实现，自动发现仍未实现

上面的条目是二维码实现前的历史快照。发布前 `codex/ai-upgrade` 工作区已加入 `desktop:lan-sync-pairing-qr`、`CWBV48.createPairingQrPayload()` / `parsePairingQrPayload()` 和 `qrcode@1.5.4`；桌面弹窗显示二维码并保留四项明文复制回退。二维码只承载短期 HTTPS 地址、工作区 ID、配对 ID、8 位配对码、证书指纹和过期时间，不自动信任证书，也不启用自动发现。真实手机扫码和证书信任仍是 v4.8.0 发布后的限制。
