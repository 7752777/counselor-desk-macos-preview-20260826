# 架构概览

## v4.9.0 局域网和可靠性架构（候选）

商业授权是独立于业务工作区的一条运行时链路：Ed25519 公钥验证许可证，Electron 通过 `safeStorage` 保存激活状态，`CWB.entitlements` 在 UI、业务入口和 AI 请求前重复守卫。更新链路使用签名清单、SHA-256、下载状态和安装失败回滚状态；独立授权服务负责发码、设备上限、撤销和管理员审计，不接触学生数据。前瞻体验阶段可使用两个长期活动兑换码，服务端按哈希查找活动并为每个工作区签发独立许可证；通用码不进入客户端，也不等同于共享许可证。当前实现已通过 Node/契约测试，生产 KMS、PostgreSQL、支付 webhook、CDN、代码签名、公证和真实跨平台升级仍需外部环境验收。

辅导员工作台 v4.8.5 延续本地优先架构：同一套业务页面可以作为网页、离线 HTML 或桌面端运行，数据处理尽量留在使用者可管理的设备上。它的目的不是搭建中心化平台，而是让一线记录、附件、导入、AI 建议、查课查寝、量化考评、局域网协同和恢复有清楚的边界。v4.8.3、v4.8.2、v4.8.1、v4.8.0 作为历史维护基线保留；仓库现已私有，Pages、附件和发布状态以当前版本收尾记录为准。

所有历史批次、当前发布、AI 链路和未完成风险的总账见[全量开发计划对账](./upgrade/full-plan-reconciliation-2026-08-19.md)；v4.8.5 的发布事实见[发布收尾记录](./upgrade/release-v4.8.5.md)，模型按钮和额度核对见[AI 模型可用性审计](./upgrade/ai-provider-readiness-audit-2026-08-21.md)。

## 三个使用层

| 层 | 作用 | 使用者关心什么 |
| --- | --- | --- |
| 网页与离线 HTML | 快速打开、演示、轻量使用 | 浏览器数据不会自动迁移到另一台电脑；便携模式不会读取或写入普通网页的数据空间。 |
| 桌面端 | 固定电脑上的本地资料、附件与备份 | 用户数据与安装目录分开；升级、卸载和换机前应先建立备份。 |

## v4.5.0 / v4.6.0 / v4.7.0 数据工作区

v4.5.0 使用 **schema v8** 作为公开工作区数据格式。v4.6.0 通过 v8 → v9 增量迁移新增住宿、班委、家长联系、工作记录草稿和科研集合；迁移时保留稳定内部 ID、附件关联、历史学号和自定义字段，并在转换前创建恢复点。数据写入通过串行队列处理，提供保存状态、失败重试、版本历史、恢复点和诊断信息；浏览器主存不可用时会进入可见的兼容模式并提示应急导出。新增集合作为独立工作区边界进入备份、交换和跨端同步，不自动改写学生事实。

为保持已有扩展和自动化脚本的兼容性，`window.CWB` 继续可用；同时公开以下稳定命名空间：

| 接口 | 用途 |
| --- | --- |
| `CWB.workspace` | 写入、检查点、刷新、状态、重试、版本历史和恢复。 |
| `CWB.views` | 个人列视图、筛选方案与显示配置。 |
| `CWB.leadershipViews` | 领导统计视图的数值指标、保存视图、选择、编辑、删除与导出支持。 |
| `CWB.imports` | 导入任务、进度、暂停、取消、重试与冲突处理。 |
| `CWB.exports` | 字段选择、脱敏、版式与导出审计。 |
| `CWB.diagnostics` | 存储状态、异常信息和应急诊断包。 |
| `CWB.utilities` | 本地抽签、分组、轮值、日期计算和名单清理。 |
| `CWBV46` | v4.6 宿舍、班委、家长联系、工作记录、科研和班级分析规则。 |
| `CWBV46UI` | v4.6 页面、草稿确认、导入导出和当前页入口。 |

附件二进制仍由专门的附件仓保存；工作区只保存附件元数据和关联关系，避免把大文件复制进每一条版本历史。

业务关联有一个不可省略的边界：只有明确的 `student_id` 才能把业务记录连接到学生。业务记录自身的 `id` 不参与学生 ID 回退；从学生集合读取的对象才可以用稳定对象 ID 生成排宿、统计或工作草稿输入。这样可以避免“记录存在但被错误挂到另一名学生”的隐性数据污染。

住宿采用“预览 -> 再验证 -> 人工确认 -> 写入快照”的流程。排宿确认时重新读取当前 assignments、楼栋和房间状态，任何床位、性别、容量或重复入住冲突都会中止写入。调宿历史使用追加记录和作废状态，不用硬删除破坏时间轴。奖惩证书和其他业务附件走附件仓，删除时先检查共享引用。

学生画像的敏感显示采用“默认脱敏 -> 访问锁验证 -> 审计记录”的路径。电话不会因为工作台没有配置访问锁而直接显示完整值；班级分析默认只渲染聚合结果，个人明细和指标下钻复用同一访问控制入口。工作记录草稿在确认前会重新比对来源哈希，过期或已删除来源不能静默写入正式留痕。

领导统计视图存放在工作区设置的 `leadership_views` 与 `leadership_view_id` 字段中。它与个人列视图分开，避免字段配置的异步写入覆盖统计视图；任何共享设置写入都必须保留这两个字段。旧版存于 `personal_views` 且标记为 `kind: 'leadership'` 的记录会在读取时规范化并补齐默认指标。

## 设计原则

- **本地优先**：不强制项目账号，不把学生业务数据设计为项目服务器的默认资产。
- **显式确认**：导入、覆盖、删除、恢复等高风险动作先预览、确认并留下退路。
- **可携带**：数据通过明确的导出与备份路径迁移，而不是被锁在某个浏览器或安装目录中。
- **兼容优先**：面对不同学校的表头和字段口径，先保留信息，再逐步规范。
- **验证优先**：网页、桌面端、附件、迁移和恢复需要各自测试；任一平台未验证，不包装成“全平台完成”。

## v4.7 跨端资源边界

源码网页依赖 `src/core` 下的版本化运行时；离线构建由 `scripts/build-release.js` 将 v4.6/v4.7/v4.8 业务、v9/v10/v11 迁移和 UI 内联。Electron 的根 `electron-builder.yml` 必须显式打包全部外部运行时；Pages workflow 必须复制与 `index.html` 匹配的脚本。任何一端缺少 `cwb-v46-ui.js`、`v10-migration.js`、`v11-migration.js`、`cwb-v47-ui.js` 或 `cwb-v48-ui.js` 都会表现为入口缺失而不是数据迁移错误，因此发布前要分别检查网页、离线包、Electron 和 Pages 资源。

浏览器入口的内嵌集合 manifest 不是可手工漂移的第二份 schema；发布构建会从 `src/core/cwb-collections.js` 刷新它。测试必须比较内嵌清单与共享清单的内容和顺序，尤其不能漏掉照片待确认队列等辅助业务集合。

活动参与统计是关系派生而不是重复事实表：使用 `student_id + term + activity_id` 作为去重键；无法唯一匹配的旧自由文本继续留在原活动记录中，不会被猜测加入学生统计。学生时间线同样从稳定 ID 回链家校联系、住宿轨迹、班委考核和活动参与，主活动已有明确参与人时避免重复事件。

局域网主机、客户端连接/拉取/推送/离线队列、冲突收件箱页面、v11 迁移、学生身份导入核心和桌面备份定时检查已经在 v4.8.0 交付；主机同步操作会回写真实 Electron SQLite，并通过可注入回调记录最小同步审计。附件客户端分块上传/下载、主机正式附件和临时分块加密落盘、备份运行记录以及只传输加密包的 HTTPS/WebDAV 适配器核心也已交付。远程备份页面已提供配置、测试连接、上传、下载预览恢复和删除；学生台账已提供批量编辑/归档/删除/撤销。心理录音页面、工作分类、内容推送/内容包、联合走访和受支持 DOCX 任务也已交付。手机真实 HTTPS 信任/自动发现、真实 WebDAV 服务商互操作、Windows/macOS 实机恢复回滚、真实设备长时间断网重连和逐集合跨端读写抽查列为发布后限制。脱敏夹具的跨端恢复契约已通过，但不替代实机验收。完整范围见[v4.8.0 客户反馈执行方案](./upgrade/customer-feedback-execution-plan-2026-08-21.md)，真实落地状态见[客户反馈逐项审计](./upgrade/customer-feedback-audit-2026-08-21.md)。

v4.8.0 业务运行时由 `src/core/cwb-v48.js` 提供身份优先导入、批量操作契约、受支持表单解析、派生分析、敏感语音规则、备份调度、同步主机/客户端、字段目录、内容推送、工作分类和联合走访查询；`src/core/cwb-v48-ui.js` 只负责页面入口和操作状态，不建立第二套事实数据。心理录音实际由 `index.html` 负责 MediaRecorder、逐次授权、relay 调用和人工确认；原音频只在会话内存中存在。受支持 DOCX 通过附件 ID 和 JSZip 处理，反向汇总只读取内容控件并导出结构化 CSV，不自动写回学生事实。

内容推送采用“核心服务权限 + 页面当前上下文”两层判断。核心服务规范化本地策略角色、检查 `audience_roles` 和 `scope`，页面把当前工作区的学院/年级/班级上下文传给列表、已读和导出；普通角色不能依赖空上下文获得全量内容，管理员全量导出仍由核心权限明确放行。该策略不等于账号认证，局域网同步也不因此共享学生明细。

工作留痕导出在运行时从来源集合重新解析来源记录，输出来源字段和顶层 `provenance`。它是审计和人工回查辅助，不是事实复制机制；来源删除或变化仍由工作草稿来源复核链处理。`tests/v48-worklog-export-runtime.js` 加载实际构建产物验证该关系，避免仅用源码静态断言。

## AI 跨模块链路

AI 不是事实数据仓库，也不是后台自动执行器。一次请求按以下边界流转：

```text
当前页面/学生/事项选择
        -> 上下文构建与 student_id 范围过滤
        -> 脱敏预览与一次性授权（如需要）
        -> provider 或受控 relay 请求
        -> 生成审计 + 草稿 + 建议
        -> 人工查看/采纳
        -> 经过来源复核后转任务、谈话或工作留痕
```

`src/core/cwb-ai.js` 只负责 provider、请求、脱敏基础能力、来源 URL 校验和审计记录规范化；`src/core/cwb-ai-workflow.js` 负责授权、来源状态、建议风险、IPv6/保留地址复用和状态转移；`index.html` 负责从本地工作区构建上下文、保存集合和绑定页面动作。生成审计会回填 `suggestion_id`、`draft_id`、`source_ids`、`context_scope`、敏感分类/字段、截断状态和耗时；确认审计通过 `parent_audit_id` 回到生成审计。来源目录中的本地记录使用稳定来源 ID和业务指纹，建议转化前重新读取原始集合，防止旧摘要被当成新事实。公共运行入口对只有学号快照的直接记录/来源先解析稳定 `student_id` 再做范围比较。

任务、谈话、工作留痕、奖惩证书和通用 v4 记录只保存 AI 元数据和附件 ID，不保存 API key、relay token 或请求正文。临时生成文本和原始请求内容只保留在当前内存或显式 AI 草稿中，不写入持久化 `ui_state`。模型“测试连接”使用无业务上下文的最小消息，结果只记录成功/失败、模型、耗时和安全错误码。

当前 v4.8.0 请求运行时又增加了明确的防护：`readJsonPayload()` 在直连 provider 的 JSON 解析前执行 `content-length` 和 UTF-8 字节上限；请求取消会在响应体读取后再次检查，取消竞态不会生成成功事实；图片请求在工作流和 provider 适配层均校验 `supportsVision`，Anthropic 适配器把 `image_url` 转为 `image/source.base64`；出站消息只允许安全角色、文本和受校验的图片 data URL。建议质量反馈只写入既有 `v4_ai_audit`，由 `CWB.ai.metrics.summary()` 返回按最新建议反馈的统计。

当前仍需单独完成数据库级加密、真实模型质量评分、长期设备压力测试、来源版本化/语义检索和建议相似度去重；本地来源的稳定回链与“变更/删除后阻止转化”已在当前候选中完成，但不能替代上述长期能力。

## AI 请求与确认边界（2026-08-20）

AI 路径分为四层：

1. 页面/公共入口构建当前学生、班级、事项和来源范围，并显示敏感授权预览。
2. `CWB.ai.run()` 校验用途、provider、额度、稳定 ID 范围、来源指纹和一次性授权，然后执行出站脱敏。
3. `CWBAI` 负责协议适配、relay/SSRF/响应大小/取消控制；relay 对公开来源 URL 再做一次令牌参数清理。
4. 生成结果只写建议或草稿；只有带人工确认链且来源仍可核验时，才允许转成任务、谈话或工作留痕。

连接测试是独立的 `provider_test` 审计，不携带业务上下文，也不消耗每日模型生成额度；取消审计使用 `cancelled` 状态。`identity` 授权按当前范围放行姓名/学号，但 `student_id` 和本地记录索引永远不出站。

## 记录级 AI 入口维护（2026-08-20）

AI 页面采用“页面入口 -> 本地上下文构建 -> 出站治理 -> 建议/草稿 -> 人工确认”的单向链路。页面记录动作只携带目标视图、目标集合和目标记录 ID；实际模型消息由上下文构建器重新从本地集合取数、脱敏并裁剪，避免按钮上的显示文本成为事实来源。

课表、住宿当前安排和点名历史属于记录级入口的维护样例：它们分别使用 `v4_class_schedules`、`v4_dorm_assignments` 和 `v4_roll_call_sessions`，没有新增重复事实表。点名记录的业务日期字段统一为 `date`。AI 结果仍进入建议或 `v4_worklog_drafts`，不会绕过原业务写入和确认流程。入口维护清单见[AI 实现逐项对账](./upgrade/ai-implementation-reconciliation-2026-08-20.md)。

用途治理同样是单一注册表：页面显示和 provider 授权使用 canonical key，旧别名在输入和历史数据读取时归一化；未知用途在公共运行入口直接失败并记为配置错误，避免把页面拼写错误误当成工作总结执行。

## AI 输出安全与运行健康

AI 出站安全有两道边界：请求发出前由 `aiOutboundContext()`/`aiSanitizeMessages()` 清理上下文，模型返回后由 `aiSanitizeGeneratedOutput()` 清理结果文本。第二道边界专门防止模型回显内部索引或未授权身份内容进入页面、草稿和建议。`CWB.ai.createAuditEntry()` 通过 `output_redacted` 标记发生过二次清理，原始响应不进入持久化数据。

`CWB.ai.health()` 只读取当前运行时和工作区派生状态，不拥有写入权限。它把“脚本缺失、用途合同不一致、集合缺失、页面入口缺失”列为阻断项，把“未配置模型、来源待核验、建议/草稿待处理”列为提醒项。健康报告展示在 AI 工作台，不能被当作模型质量或正式发布证明。

## 保存队列与来源草稿一致性（2026-08-21）

保存层由两部分组成：一是 `save(part)` 对兼容存储、IndexedDB/Electron 适配器和 v8 workspace sync 的统一 Promise；二是 `trackedSaveQueue` 对连续写入进行串行化。`awaitTrackedSave()` 将底层 `{ ok:false }` 结果转为业务错误，使 UI 能保留当前表单或确认框并提供重试，而不会把未完成操作显示为成功。

工作记录草稿属于 `custom` 集合，但来源可以来自基础集合。来源复核或删除标记发生时，保存层通过 `pendingWorklogDraftSyncVersion` 将这次跨集合变更与触发它的基础保存一起提交；只有所有同步和工作区状态检查成功后才清除版本标记。失败重试仍会重新同步草稿，避免 v8 工作区回写旧 custom 状态。

这条路径让“按钮 -> 业务事实 -> 来源草稿 -> v8 工作区”的写入顺序可观察、可回滚。它不改变 `schema_version:8` 或 `data_schema_version:11`，也不新增集合；来源指纹字段扩展只影响来源新鲜度判断，不改变历史学生事实。指纹只取业务事实字段，明确排除 `updated_at` 等保存元数据；因为一次 `save(part)` 可能批量刷新同集合记录的时间戳，不能把这种技术性变化当成老师修改了事实。

## 延迟脚本启动协调（2026-08-21）

页面内联启动代码必须允许 `defer` 的核心脚本先完成注册，再重绘当前视图。`scheduleDeferredRuntimeReconciliation()` 在 DOM 就绪后检查 `CWB`、`CWBAI`、`CWBAIWorkflow`、`CWBV46UI` 和 `CWBV47UI`；全部就绪后更新 `CWB.ai.governance` 并只重绘一次。这样 AI 健康卡不会把“脚本尚未到达”误报成持久化接入缺口，同时真正缺失脚本仍会被健康检查阻断。

## AI provider readiness 与额度隔离（2026-08-21）

页面内联动作、统一建议中心和 AI 通知入口复用同一条 readiness 规则：先按当前选中的 provider 和用途做运行时派生检查，再决定按钮是否可用；请求开始后继续校验配置、凭据、授权、上下文和额度。这样 UI 反馈更早，但不会把前端禁用当作权限边界。

`v4_ai_audit.provider_id` 用于把成功生成绑定到具体模型连接。额度查询按 `provider_id + purpose` 统计，旧记录没有该字段时按连接器和模型名兼容匹配；连接测试、失败、取消和本地通知预览不会进入生成额度。模型 readiness 不持久化为单独集合，避免把瞬时会话凭据状态错误地当成业务事实。

## v4.8.0 数据目录与远程端点事务（2026-08-21）

桌面数据目录迁移由路径判定、临时副本、候选仓健康检查和激活事务组成。`desktop/data-target.cjs` 不依赖 Electron，负责在路径规范化前拒绝空值并阻止工作区嵌套；`desktop/data-directory.cjs` 在候选仓 `verifyPayloads` 通过后才切换活动仓，激活失败重新打开原仓，回滚失败则把活动仓置空并返回 `DATA_MIGRATION_ROLLBACK_FAILED`。这样“目标路径解析错误”和“仓储无法恢复”不会混成一个普通 IPC 错误，也不会通过生成新密钥掩盖旧库损坏。

远程备份适配器把 base URL 和端点路径分开校验：基址只允许无凭据、无查询参数的 HTTPS 地址；端点只能是同源相对路径，拒绝绝对 URL、反斜杠、查询/片段和编码目录穿越。URL 在 fetch 前解析，参数错误不会被网络错误处理器覆盖。该层只传输已加密 `.cwbk`，不承载密钥、令牌或明文附件。

局域网配对仍采用“主机生成一次性配对信息 -> 客户端扫码或手动提交 -> 主机人工确认”的链路。桌面 UI 可显示二维码并提供地址、配对 ID、配对码和证书指纹复制回退；当前没有自动发现，也不会替用户自动信任证书。真实手机扫码、证书信任和长期重连属于发布后设备抽查，不应被文档扩大解释为自动接入。

## v4.8.0 同步事务边界（2026-08-21）

局域网主机采用“状态快照 + 业务仓储回退”的提交模型：

```text
客户端操作
  -> 主机校验设备/范围/版本
  -> 保存同步状态快照和业务旧值
  -> 写入业务仓储
  -> 原子写入加密同步状态
  -> 成功响应
```

任一步失败都恢复同步状态；业务记录由 `recordStore.get/put/delete` 回退。Electron 主进程不让客户端直接访问 SQLite 文件，主机状态和附件仓分离保存。客户端先校验 HTTPS 和证书指纹，网络层只捕获真正的连接失败，配置错误保留可操作错误码。

同步审计在事务提交后发送，不能在业务写入或状态文件写入之前记录成功事件；这样审计、同步状态和 SQLite 事实不会互相矛盾。

### v4.8.0 配对与客户端状态边界

局域网主机的配对分为请求、人工确认、一次性令牌交付三个阶段。请求 ID和设备 ID绑定；确认后令牌只在主机内存交付表中短暂存在，客户端通过 `/api/v1/pairing/result`领取一次，领取后删除。持久化快照只保存令牌哈希和设备状态，公开状态投影会剔除令牌哈希。

设备状态 `active`、`paused`、`revoked`由主机事务修改。暂停不删除业务数据或离线队列，但所有需要设备认证的同步和附件路由统一拒绝；冲突解决和附件上传不能绕过暂停。客户端将队列、游标、冲突摘要和错误码持久化，令牌仅保留在运行时内存；自动同步调度由当前页面/桌面进程显式启动，不在浏览器关闭后继续运行。

### 局域网配对二维码的边界

二维码由 Electron 主进程生成，`desktop/main.cjs` 只把 `CWBV48.createPairingQrPayload()` 产生的白名单 URI 交给 `qrcode@1.5.4` 渲染为 PNG Data URL；预加载层不允许页面传入任意二维码文本。主机地址、工作区标识、一次性配对信息、指纹和过期时间由当前运行中的主机状态组合，主机管理令牌和设备令牌不经过渲染器。

页面显示二维码后仍要求用户核对 HTTPS 地址和证书指纹。扫描仅帮助填写连接信息，后续仍执行配对请求、主机人工确认和一次性令牌领取。没有二维码能力时，四项明文复制按钮是兼容回退。当前实现没有局域网自动发现，也没有替用户自动信任自签名证书；真实手机扫码与证书信任属于最终发布前的设备验收项。

## 2026-08-22 当前实现边界

2026-08-22 的按钮级维护又确认两条架构约束：证书识别只允许一个安全入口，生成输出先进入 v4_ai_drafts，人工确认后才跨写 rewards；建议批量审阅以 v4_ai_suggestions 与 v4_ai_audit 快照为事务边界，只有持久化成功才清理 UI 选择。若同步或仓储失败，内存状态必须恢复，不能把渲染完成当成提交完成。

当前架构审计总账见[当前收口总账](./upgrade/closeout-status-2026-08-22.md)。v4.8.0 已把 AI 建议/通知/授权的持久化等待和失败回滚、局域网队列存储能力提示及跨工作区隔离纳入实现与回归；v4.8.1 完成安全提示维护；v4.8.2 完成同步客户端状态保存和业务仓储失败回退；v4.8.3 完成学生台账 AI 操作列和移动资料/分页布局收口；v4.8.5 完成单文件离线图标内联、`file://` 全导航和本地 HTTPS/WebDAV 传输门禁。真实设备、长期同步、第三方 WebDAV、数据库级加密和签名安装仍不能由浏览器/JSDOM 契约测试替代，按发布后限制维护。

AI 公共写入的兼容层现在由对象级 `ready` Promise 承担最终保存承诺；`CWB.ai.awaitMutation()` 和 `*Async` 方法将同步兼容返回值转换为可等待事务。审计仓则对高风险动作使用强制失败语义，对普通动作返回结构化延迟失败状态。任何跨集合业务事务都必须继续以快照、保存结果和失败回滚为最终边界，不能把 DOM 重绘或 toast 当作提交完成。

## v4.9.0 商业控制面

商业授权是业务数据之外的控制面：Electron 通过 `safeStorage` 保存授权状态，业务 SQLite/IndexedDB、备份、手机交换包、学生导出和普通审计只保留非敏感授权状态，不保存许可证 token、设备令牌或模型密钥。`CWB.entitlements` 同时保护 UI、业务函数和请求发送前路径；页面灰色按钮不是唯一权限边界。

工作区身份由 `DB.settings.workspace_id` 持久化保存。v4.9.0 启动迁移会为缺失、空值或保留回退值（`local-workspace`、`workspace-local`）的旧工作区生成随机稳定 ID，并只增量写回设置；已有合法 ID 不会改写，组织代码也不再作为商业授权的隐式工作区 ID。这样同一通用兑换码可以跨多个工作区使用，但每个工作区仍独立签发许可证和设备额度。恢复同一工作区必须保留该字段；复制工作区会复制授权身份，产品不把它当成匿名克隆机制。

授权服务独立于工作台业务仓：Fastify 只接收订单、许可证、设备、支付事件摘要、邮件 outbox 和更新清单；PostgreSQL 通过参数化 SQL 与事务写入，KMS/HSM 负责签名。服务端不接收学生数据、业务附件、AI 输入或模型 Key。订单访问令牌只以服务端密钥派生值交付，数据库保存哈希和 7 天过期时间；生产 CORS 采用精确 HTTPS 来源清单。

更新控制面与数据迁移解耦：清单签名、平台安装包签名和 SHA-256 在客户端更新前验证；安装前创建恢复点，数据目录不随安装目录移动。许可证丢失只影响重新激活，不提供从业务备份恢复授权的后门；更新失败应恢复工作区快照而不是生成新密钥覆盖旧数据。真实 PostgreSQL、KMS、支付、CDN、证书和公证属于部署证据，不由本地契约测试替代。

### v4.9.0 更新回滚与客户交付边界

Electron 更新 runtime 将“下载包可信”和“安装后工作区健康”分开处理：先验签清单原始内容、SHA-256 和平台签名，再创建恢复点；安装阶段把目标版本与恢复点元数据写入 `vault/update-install-state.json`。新进程启动后如果版本未达到目标，或 SQLite/WAL/附件健康检查失败，会把当前目录改名保留并恢复经过校验的快照。恢复失败保留两份目录并停止继续覆盖，不生成新密钥。平台命令封装在 `desktop/platform-signature.cjs`，契约测试使用注入命令结果，真实证书和公证仍由 Windows/macOS 发布机证明。

客户购买页和授权服务是独立控制面。`/customer` 只接触产品、订单和许可证元数据；订单访问 token 以服务端哈希保存，普通订单查询不返回激活码，许可证下载必须经令牌认证且 `no-store`。客户页不是支付服务，未接入真实支付 webhook 前只能显示待确认状态。许可证、设备 token、Relay assertion 和模型 Key 永不进入学生业务仓、备份、交换包或普通日志。
