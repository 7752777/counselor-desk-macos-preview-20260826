# 激活安全模型

## 保护对象

- 许可证签名私钥：只在授权服务或 KMS/HSM。
- 客户激活凭据：Electron `safeStorage` 专用文件；不写业务 SQLite、备份或交换包。
- 模型 API Key：沿用现有 AI 安全存储，不与许可证混用。
- 学生业务数据：不发送给授权服务；授权请求只包含许可证编号、工作区绑定标识和设备标识。

## 客户端校验顺序

1. 解析 `CWB-LIC-1` 三段格式和严格 base64url。
2. 用 `kid` 选择公钥并验证 Ed25519 签名。
3. 校验产品、档位、主版本、状态、设备上限字段和时间。
4. 在线激活由服务端做工作区绑定、设备注册和撤销检查。
5. 离线只使用最近一次在线状态，超过 30 天拒绝新的 AI 生成。
6. 更新动作继续检查更新权益；安全修复不因续费状态被阻断。

锁定的 AI 控件使用 `aria-disabled="true"`、`data-cwb-license-disabled="true"` 和灰度样式表达不可用，但保留 `tabindex=0`，这样键盘用户仍可以按 Enter/空格打开激活入口；业务函数和模型出站层不会把这个视觉状态当作唯一权限边界。

## 明确不是 DRM

浏览器和离线包无法提供抗逆向的 DRM；开发模式也会 fail-open 以支持测试。商业 Electron 构建必须 fail-closed 并注入生产公钥，但本地拥有者仍可控制自己的设备。在线 relay 只提高复制成本，不应向用户承诺“绝对无法破解”。

## 日志与备份规则

允许记录 `license_id`、动作、状态、时间、错误码和审计编号；禁止记录 token、完整签名载荷、模型 Key、学生姓名、学号、附件 ID 或完整授权请求。`CWB.license.getState()` 和 DOM 事件只输出脱敏授权元数据。

## 事件处理

| 事件 | 处理 |
| --- | --- |
| 许可证损坏 | 不生成新许可证覆盖旧状态；提示重新激活或恢复安全备份 |
| 设备达到上限 | 显示设备管理，需服务端解绑后再激活 |
| 退款/撤销 | 刷新后禁止新 AI 生成，但保留业务数据和已确认记录 |
| 恢复/换机 | 使用授权服务重新绑定新设备；不把许可证放进业务恢复包 |
| 时间回拨 | 暂停离线授权并要求在线校验，不自动删除数据 |

## 文件、二维码和设备解绑

许可证文件导入与实际激活是两个动作。文件或二维码只产生待激活候选，只有用户点击“激活许可证”后才会进行在线设备注册和工作区绑定；文件读取失败会保留窗口内容并给出重试或粘贴回退。二维码只接受许可证内容，不接受主密钥、学生数据或设备令牌；没有 `BarcodeDetector` 的浏览器显示明确降级提示。

用户可以在设备管理页解绑本机或其他已注册设备。解绑只撤销授权服务中的设备会话，不删除被解绑设备的 SQLite、附件、备份或学生数据；本机解绑后需要重新激活。替其他设备解绑必须携带当前有效许可证凭据并在线完成，服务端仍校验许可证、工作区和设备关系。

客户订单访问令牌与许可证激活码是两类不同凭据：订单令牌只用于查询订单和下载已签发文件，许可证激活码用于工作区激活；两者分别由 `CWB_ORDER_ACCESS_SECRET` 和 Ed25519 签名链保护，不能互换，也不能写入业务备份。

## `CWB-REL-1` 边界

AI Relay assertion 是短期、最小权限、带设备和过期时间的签名凭据。授权服务不保存用户模型 API Key，Relay 不把 assertion 转发给模型，普通日志只记录用途、设备和结果状态。没有 AI 许可证时，请求在 UI、业务函数和出站前均被阻断；有许可证但没有模型 Key 时只提示配置模型。Relay 故障不应删除已有业务记录或 AI 草稿。
