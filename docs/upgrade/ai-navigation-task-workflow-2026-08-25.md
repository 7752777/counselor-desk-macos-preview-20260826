# AI、导航与任务工作流收口记录（2026-08-25）

## 目标

把 AI 从独立聊天入口变成工作台中的上下文工具：老师在学生、任务、谈话、通知、学业、住宿、就业或资料页面看到 AI 动作；生成结果先是建议或草稿，核验后才转为任务、谈话或工作留痕。

## AI 配置的三种模式

| 模式 | 用户要填写什么 | 适合谁 | 安全边界 |
| --- | --- | --- | --- |
| 平台 AI | 选择用途并完成授权，不填写 Base URL、协议或共享 API Key | 希望开箱使用的普通用户 | 由受控 Relay 选择模型；客户端不内置共享 API Key |
| 自有 API Key | 服务商地址、模型和自己的密钥 | 有模型账户的老师或学校 | 密钥只进入当前会话/系统安全存储，不进入业务备份和普通日志 |
| 高级自建服务 | 自建 HTTPS Relay、允许域名和用途 | 学校 IT 或高级用户 | 仍执行 URL、私网地址、用途、授权、审计和请求前守卫 |

平台 AI 模式的“无需填写共享密钥”不是把密钥藏在 HTML 中，而是让服务端 Relay 负责受控转发。没有许可证不能出站；有许可证但没有模型配置时，页面会告诉用户下一步配置模型。

## 用途授权

AI 用途以可读名称展示，例如学生摘要、谈话 briefing、通知改写、学业帮扶、班级分析、就业建议、住宿冲突检查、工作留痕草稿和来源检索。心理、预警、纪律、资助、联系方式等敏感类别默认关闭。

一次敏感请求的顺序固定为：

```text
选择页面/学生/事项
→ 选择 AI 用途
→ 选择本次敏感类别（默认关闭）
→ 确认一次性授权
→ 请求前再次检查许可证、模型、用途和范围
→ 只生成建议/草稿
→ 老师编辑、核验并选择是否转化
```

AI 不自动修改学生事实、心理结论、预警、处分、资助、住宿分配、量化等级或审批状态。内部 `student_id`、记录 ID、附件 ID 和审计 ID 不出站。

## 失败、重试与日志

- 运行中显示“正在请求模型”和可用的取消动作。
- 失败或取消后保留状态、错误码和重试入口。
- 重新生成按钮使用当前进程中的临时请求文本；UI 持久化只保留不可逆的请求范围，不保存完整 Prompt、模型 Key 或响应。
- 用户编辑 Prompt 后重新点击生成会创建新的请求链，不错误继承旧失败的 `retry_of_audit_id`。
- 日志记录用途、模型、状态、请求编号、耗时、来源数量、目标页面和人工确认关联，可从 AI 日志回到原业务页面。

## 导航工作流

左侧导航的默认顺序优先服务“今天要做什么”：工作台、学生台账、谈心谈话、工作留痕和任务优先显示；低频模块可以折叠但仍能搜索。用户可以：

- 展开/折叠分组；
- 搜索被折叠的模块；
- 将模块钉到常用；
- 调整常用顺序；
- 创建自定义分类、设置颜色、编辑和删除；
- 使用上一页/下一页历史导航，恢复时保持当前视图状态。

自定义导航只保存 UI 设置，不改变业务数据；删除分类前会恢复其中的导航项，避免误删入口。

## 任务工作流

任务字段包括标题、学生/班级关联、开始日期、结束日期、截止日期、优先级、状态、来源和备注。长期维护时按以下规则处理：

- 只有截止日期：甘特图按截止日期绘制一个单日任务，不虚构开始日期。
- 只有开始日期：结束日期按开始日显示，直到用户补充结束日期或截止日期。
- 起止日期倒置：展示层按时间顺序纠正，不修改原始事实。
- 没有日期：列表保留“未设置”，不会生成虚假时间轴。
- 通知、谈话、查课、查寝和 AI 草稿转任务时保留来源 ID、来源页面和人工确认状态。
- 学生主档案变化只更新进行中事项的稳定关联快照，不改写成绩、谈话、奖惩、住宿和历史事实。

## 前瞻通用兑换码

前瞻体验用户可使用两个长期活动码，入口位于“商业授权”或任意灰色 AI 按钮的激活弹窗。活动码在线兑换后生成独立许可证；三端使用同一工作区时，许可证状态由授权控制面管理，业务数据仍按桌面主机/局域网同步规则流转。

固定码的明文不进入本仓库。生成命令只在受控终端显示一次：

```text
node services/license-server/scripts/generate-redemption-codes.cjs
```
