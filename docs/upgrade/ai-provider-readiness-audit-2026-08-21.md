# AI 模型可用性与按钮闭环审计 · 2026-08-21

## 审计目的

本次维护针对一个容易让老师困惑的场景：模型配置页面显示“已启用”，但当前浏览器没有可用密钥，或者当前用途没有授权，点击生成后才失败。目标是让按钮在点击前就给出可理解的状态，同时保留公共运行入口的二次拒绝，不能因为脚本调用或旧页面绕过 UI。

本记录描述当前工作区 `codex/ai-upgrade` 的候选改动，不代表历史 `v4.7.0` Tag、Release、Pages 或已下载离线包已经包含这些修改。

## 可用性规则

`CWBAI.providerReadiness(config, purpose, options)` 是运行时派生检查，不新增集合、不写入密钥，也不改变业务数据。生成按钮按以下顺序判断：

1. 已选择模型连接；
2. 连接处于启用状态；
3. 模型名称不为空；
4. 用途属于 canonical 用途注册表，且已被当前模型授权；
5. 图片识别用途要求 `supportsVision: true`；
6. 当前环境确实能取得凭据；
7. 当前模型、当前用途的当日成功生成次数未达到该模型自己的额度。

额度只统计 `action: generate`、`status: completed` 的记录。连接测试、失败、取消和本地通知预览不会消耗生成额度。新审计通过非敏感的 `provider_id` 绑定模型连接；旧审计没有该字段时按连接器和模型名兼容匹配，不会把不同模型的调用混在一起。

## “已设置密钥”与“当前可调用”

`secret_set: true` 只表示此前曾经完成过凭据配置，不等于当前普通浏览器会话一定能读取密钥：

- 浏览器端还必须在当前 `sessionStorage` 中存在对应密钥；关闭会话、清理站点数据或更换浏览器后可能失效。
- Electron 端通过安全存储接口读取凭据，`secret_set` 与安全存储中的可用标志共同参与运行时检查；最终请求前仍会再次读取，读取失败会产生 `AI_API_KEY_REQUIRED` 审计。
- API 密钥、relay 令牌和原始模型响应不进入业务备份、交换包、日志、`ui_state` 或本文件。

因此页面同时展示“模型已就绪”“当前会话未设置 API 密钥”“当前模型未授权此用途”等状态，不把“启用”误写成“可调用”。

## 按钮行为

| 入口 | 没有可调用模型时 | 就绪后 | 失败后 |
| --- | --- | --- | --- |
| AI 工作台生成 | 禁用并显示添加/配置模型 | 允许生成草稿 | 保留重试入口和安全错误码 |
| 页面内 AI 动作 | 禁用并标明用途或模型原因 | 绑定当前页面/记录上下文 | 不写入事实记录 |
| 预警、证书等专用动作 | 额外检查用途或视觉能力 | 只生成建议/草稿 | 不自动修改专业结论 |
| 连接测试 | 只检查连接、模型和凭据 | 发送无业务上下文测试 | 记录连接测试状态，不扣生成额度 |
| 通知本地预览 | 不受模型配置影响 | 可继续解析主动粘贴的通知 | 失败可改用本地结果或重试 |

AI 通知的本地预览只处理老师主动粘贴或导入的文本，不读取钉钉、学校系统或浏览器后台通知；它可以生成标题、重点、待办和待核验项的本地草稿，所以在没有真实模型时仍保留这条低风险工作流。

## 数据与迁移边界

- `v4_ai_audit.provider_id` 是可选、非敏感的连接标识，用于额度隔离和审计回链。
- 旧审计缺少 `provider_id` 时按既有 `provider` + `model` 读取，不要求重写历史记录。
- `providerReadiness`、AI 健康卡和按钮禁用状态都是当前运行时派生结果，不创建 `v4_ai_readiness` 集合。
- `schema_version: 8` 和业务 `data_schema_version: 10` 不因本次 readiness 修复变化。
- 备份、恢复、IndexedDB、Electron 和交换包必须保留新审计字段；密钥仍由安全存储或当前会话单独管理。

## 仍然需要人工验收的风险

- 真实模型的网络、协议兼容性、中文质量和图片识别质量不能由 readiness 检查证明。
- 普通浏览器会话密钥丢失后需要重新配置；这属于安全边界，不应通过把密钥写入业务数据来“自动恢复”。
- 历史上已经暴露过的外部 API key 仍必须在服务商后台撤销并轮换。
- 当前候选已生成 Web 单文件候选，但尚未创建新的 Tag/Release、尚未生成最终桌面安装包，也尚未部署 Pages。
