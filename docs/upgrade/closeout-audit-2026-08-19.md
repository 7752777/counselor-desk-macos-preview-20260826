# v4.6.0 发布后收尾查漏补缺审计（已并入 v4.7.0）

日期：2026-08-19  
基线：`v4.6.0`（已公开 Release、Tag 和 Pages）  
工作分支：`codex/ai-upgrade`

本页记录公开 v4.6.0 之后、v4.7.0 正式发布前对当前工作区进行的细节审计、实际修复和局部验证。审计结论与修复已随 v4.7.0 Tag、Release 和 Pages 一并公开；本页保留逐条验证轨迹，不移动、不重写已经公开的 `v4.6.0` 或 `v4.7.0` Tag/Release。公开版本之后新增的纯 UI 收口候选不在本页的发布事实内，见[UI 收口与历史需求查漏补缺审计](./ui-redesign-closeout-audit-2026-08-19.md)。

## 审计结论

本轮没有发现需要回滚公开版本的阻断性问题。先前收尾发现的边界问题继续保留，本次又完成了学生隐私、跨模块统计、草稿来源和附件引用的细节收口：

1. 业务记录在缺少明确 `student_id` 时，不能再把记录自身的 `id` 当作学生 ID。学生对象在生成排宿方案或聚合分析时仍可以使用稳定的学生对象 ID。
2. 日期工具拒绝不存在的日历日期，例如 `2026-02-31`，不再让 JavaScript 自动归一化到三月。
3. 排宿方案确认时重新检查当前住宿记录、床位占用、房间状态和楼栋状态，防止预览后数据变化造成重复入住。
4. 调宿只允许选择启用楼栋、可用房间和属于该房间的床位；调宿历史改为作废标记，不再直接删除轨迹。
5. 浏览器离线启动时的内嵌集合清单补齐 `v4_photo_queue`，并增加与共享清单的顺序和内容一致性测试。
6. 奖惩手工录入增加证书/证明材料上传入口。二进制写入附件仓，奖惩记录只保存附件 ID；删除记录时仅清理不再被引用的附件并记录审计。
7. 学生档案编辑页增加直接补传学生照片入口；学生电话和家长电话在画像中默认脱敏，完整号码必须启用工作台访问锁后查看，并写入访问审计。未启用访问锁时不再以“点击即可查看”制造安全错觉。
8. 班级分析真正按记录 `term` 过滤；活动统计按 `student_id + term + activity_id` 去重。分析页默认只显示班级聚合，不直接渲染姓名、学号、重点关注和学业预警明细；个人明细和指标下钻都要经过访问锁。
9. 来源发生变化或被删除的工作记录草稿不能直接归档。确认前会重新计算来源哈希；过期草稿必须编辑并明确勾选“我已重新核对来源”，已删除来源不可确认。
10. 奖惩附件引用检查覆盖同一集合的其他记录，避免共享证书被误判为孤儿而删除；活动重复参与记录不再被重复计数。
11. 学生时间线补齐家校联系、住宿安排、调宿历史、班委考核和活动参与；活动主记录存在明确参与学生时，时间线不再重复展示同一事件。
12. 修复来源已变化草稿的重新核对闭环：来源仍存在时，编辑并勾选“我已重新核对来源记录”会刷新来源哈希后恢复确认；来源已删除时继续保持不可归档，并显示可操作的中文提示。
13. 修复学生档案中可选联系方式按钮的空元素绑定：学生或家长电话未填写时不再向不存在的按钮绑定事件，打开档案不会产生运行时错误；同时让 CRUD 烟测跳过文件控件赋值，避免测试工具把二进制输入误当作文本字段。

另外修复了学生台账桌面端显示模式操作路径：表格、卡片和照片使用独立动作处理，三种模式都能真正驱动渲染。卡片包含照片、班级、宿舍、导师、班主任和家长关系等信息；电话默认脱敏，照片仍由附件仓提供，不把二进制写回 localStorage。

## 保持不变的边界

- `student_id` 是业务关联主键；学号是当前快照，历史学号用于兼容匹配，不是新的身份。
- 排宿先预览、再人工确认；AI 不决定楼栋、房间或床位。
- 工作记录由来源行为生成待确认草稿，确认前不写入正式事实。
- 来源已变化的草稿必须重新核对来源；来源删除后不能用旧草稿补写正式留痕。
- 班委等级、奖惩事实、科研审批、心理、危机、纪律和资助结论不能由 AI 自动修改。
- 班级分析默认只提供聚合数；访问个人明细、指标下钻和完整联系方式属于受控敏感查看。
- 重点学生锁只是防误看，不是数据库加密。备份、系统账户、磁盘加密和受控设备仍是必要措施。
- 附件二进制不写入 `localStorage` 或业务 JSON；浏览器使用 IndexedDB，桌面端使用附件仓，便携包按附件清单迁移。
- v4.6.0 的历史 Release 附件、哈希、Pages 和跨平台构建证据继续以[发布收尾记录](./release-v4.6.0.md)为准；本页收口修复的正式公开证据以[v4.7.0 发布收尾记录](./release-v4.7.0.md)为准。

## 发布后仍待长期处理

- 真正的数据库级加密和忘记密码后的恢复策略仍需独立的高风险安全设计，当前版本不宣称已经完成。
- Windows/macOS 代码签名、公证和真实学校设备上的长时间压力测试仍以发布记录中的限制为准。
- 公开 Pages 不适合真实学生敏感资料；AI 静态部署仍需要由使用方维护受控 HTTPS relay。
- 本轮没有宣称完成真实学生照片、证书附件和 10,000 条业务记录的长时间设备压力测试；定向测试使用脱敏或合成数据，真实数据演练必须在受控设备执行。

## 后续维护顺序

1. 在受控设备和脱敏数据上继续做包含学生照片、奖惩证书、宿舍调宿和 v9 备份恢复的综合回归；当前自动化覆盖不等于真实学校设备长时间压力测试。
2. 在 Electron 独立测试工作区继续抽查学生卡片、照片上传、共享附件删除保护、班级明细访问锁和调宿作废流程。
3. 后续若继续修改，应基于新的提交创建新的维护版本，重新生成发布证据并保留 v4.7.0 历史记录；不得把本页的局部验证替代新版本门禁。
4. 旋转历史上曾经暴露过的 API 密钥；密钥不得写入源码、文档、备份、日志或 Release 附件。

## 2026-08-20 后续交互收口（不属于历史 v4.7.0）

历史收尾之后，当前工作区继续核对了“按钮是否真正完成工作”的连续路径。工具结果、科研阶段任务和 AI/业务转化使用稳定来源键，重复点击不会创建重复记录；带附件的家校联系、科研阶段和调宿保存失败会回滚未被引用附件。删除业务记录后，来源工作记录草稿会标记为来源已删除，来源变化则必须重新核对并刷新哈希；共享附件只在没有其他引用时清理。
