# v4.9.0 商业闭环、平台选型与上线执行方案

更新时间：2026-08-23

## 结论先行

商业产品不是“把激活码放到某个网盘”就完成了。必须把支付、许可证、安装包、数据同步和售后拆成可以核验的环节：

```text
产品内入口
    ↓
购买/订单页（展示价格、收款状态、取件说明）
    ↓ 支付平台签名回调或人工后台确认
独立授权服务（PostgreSQL + KMS/HSM + Ed25519）
    ↓
订单页/邮件交付许可证
    ↓
受控下载中心（Windows/macOS/Web/离线包，签名和 SHA-256）
    ↓
Electron 桌面端激活并作为局域网主机
    ↓
手机/网页端一次性配对，数据和附件通过同步 API 互传
```

当前仓库实现的是上述链路的客户端、授权服务候选、订单状态和契约测试，不是已经完成外部部署的商城。真实支付账户、KMS、域名、TLS、邮件、下载 CDN、Windows 签名和 macOS 公证完成前，版本只能称为 v4.9.0 商业候选。

产品内的商业中心是唯一用户入口：用户先用样例数据体验，再在工作台选档。购买地址接通后，选中的 `plan` 会带入订单页；已激活用户选择更高档位时进入服务端升级订单，由服务端抵扣原档位并计算差价。链动小铺不是第二个产品入口，只是微信支付商户未就绪时的临时收款/交付渠道。

## 平台如何分工

| 环节 | 推荐承载 | 负责什么 | 不负责什么 |
| --- | --- | --- | --- |
| 收款和商品展示 | 自有购买页 + 微信支付；过渡期可用链动小铺 | 商品、支付、订单、退款入口 | 不持有授权私钥，不读取学生数据 |
| 许可证签发 | 独立 license-server | 订单确认、Ed25519 签发、设备上限、撤销、换机和审计 | 不接收学生资料、附件、模型 Key |
| 数据库 | 托管 PostgreSQL | 许可证、订单元数据、设备和审计 | 不存业务工作区 |
| 私钥 | KMS/HSM 或独立密钥服务 | 签名和密钥轮换 | 不进入 Git、安装包、日志和备份 |
| 安装包 | 受控下载中心/CDN | 下载、版本说明、SHA-256、签名安装包 | 不发放许可证私钥 |
| 产品开发 | Cloud Studio 或本地开发环境 | 编码、预览、协作开发 | 不作为生产数据库、支付系统或密钥保险箱 |
| 业务数据 | 用户桌面端/局域网主机 | SQLite、附件、工作区、备份和同步 | 不因购买自动上传云端 |

### 链动小铺核实结果

2026-08-23 通过官网 [ldxp.cn](https://www.ldxp.cn/) 读取到的公开能力包括：数字卡密/数字资源/知识付费等商品类型、商家中心、自动发货、优惠营销，以及支付宝、微信、云闪付等支付描述。它适合做低成本试运营的虚拟商品销售入口。

公开首页没有提供足以证明“可直接调用本项目许可证签发服务”的完整 API/webhook 规格。因此：

- 试运营可以配置四个商品，交付预生成的、每份独立签名的 `.cwb-license` 文件；许可证在第一次激活时绑定工作区。
- 正式运营优先让支付平台 webhook 回调独立授权服务，由授权服务按订单事务签发许可证。
- 在平台没有官方签名回调或退款通知前，不能让浏览器回调、截图或用户手工点击决定“已付款”。
- 不把库存激活码放在公开百度网盘。若临时人工交付，也要通过受控订单取件页和服务端审计。

### Cloud Studio 核实结果

当前官方入口为 [cloudstudio.net](https://cloudstudio.net/)，页面定位为 Cloud Studio 云端 IDE、开发者文档和 AI 学习社区。它可以作为开发和演示环境，但不应直接承载生产授权数据库、支付 webhook、KMS 私钥、学生数据或附件。生产授权服务应部署在具备固定域名、HTTPS、数据库、密钥托管、备份、监控和限流能力的正式云主机/容器平台。

## 用户实际购买链路

### 推荐正式链路

1. 用户在工作台点击“购买许可证”，进入受控购买页。
2. 用户选择普通版、普通永久更新版、AI 增强版或永久 AI 增强版，提交邮箱/订单标识。
3. 服务端创建幂等订单，页面明确显示“待付款”，不把创建订单当成支付成功。
4. 用户跳转支付平台完成付款；支付平台把带签名的成功/退款事件发到 `/api/v1/orders/webhook`。
5. 服务端验证平台签名、时间窗口、事件 ID 和金额/商品，事务性确认订单并签发独立许可证。
6. 订单页刷新为“已完成”，或者邮件 outbox 投递受保护取件链接。
7. 用户下载 Electron 安装包和许可证文件，安装后导入许可证并在线激活。
8. 用户在“平台联动”启动局域网主机，手机和浏览器通过一次性配对码接入。

支付失败、支付超时、重复 webhook、金额不一致、退款和许可证签发失败都必须进入明确状态和人工处理队列，不能让用户凭截图继续使用。

### 试运营低成本链路

如果暂时没有微信支付商户号或支付 webhook，可以把链动小铺作为四个独立数字商品的临时付款页。工作台仍负责展示产品和激活入口，用户从所选档位进入对应的临时付款页；每次交付一个预先签名的独立许可证文件。每次生成库存时记录 `license_id`、商品档位、批次、生成时间和库存状态；平台订单号与库存记录人工核对。该方案适合小规模前瞻体验，不具备正式支付回调、自动退款撤销和高并发售后能力。规模上来后必须切换到推荐正式链路。

### 用户升级订单

升级不复用普通新购接口，也不让客户端传入最终金额。桌面端只发送当前许可证、当前工作区、当前设备和目标档位；授权服务完成签名验证和设备验证，再从产品目录计算：

```text
应付差价 = 目标档位价格 - 当前档位价格
```

升级订单会保存 `upgrade_from_license_id`、原档位和目标档位，不保存学生资料。支付成功后才签发新的许可证；支付失败、金额异常或回调重复都不会解锁 AI。

## 用户下载什么

下载中心至少提供：

- Windows 安装包：代码签名、版本、架构、SHA-256 和发布日期；安装程序允许自定义程序目录。
- macOS Universal 安装包：Developer ID 签名、公证状态、SHA-256 和发布日期。
- 网页入口：在线地址和当前版本。
- 单文件离线包：版本、适用浏览器、SHA-256 和“关闭页面后不能后台更新”的提示。
- 用户手册：普通用户版[购买、激活、更新与互通说明](../customer-quickstart-v4.9.0.md)。

客户端只内置购买地址和下载中心地址，不内置支付密钥、签发私钥、订单访问令牌或模型 API Key。构建配置使用：

```text
CWB_LICENSE_SERVICE_URL
CWB_LICENSE_PUBLIC_KEYS_JSON
CWB_UPDATE_FEED_URL
CWB_UPDATE_MANIFEST_URL
CWB_PURCHASE_URL
CWB_DOWNLOAD_CENTER_URL
```

这些值只能是公开 HTTPS 地址。`CWB_DOWNLOAD_CENTER_URL` 已接入桌面配置和工作台商业中心；没有配置时按钮保持禁用并提示联系维护者，不伪造下载成功。

## 三端数据和授权关系

### 数据路径

```text
Electron 主机：SQLite + 加密附件仓 + 审计
       ↑ HTTPS + 证书指纹 + 配对令牌
手机网页 / 浏览器网页 / 其他桌面端
```

客户端不直接共享 SQLite 文件。主机负责事务、版本、附件分块、哈希校验、审计和冲突收件箱。主机离线时，客户端保留加密离线队列；恢复后使用 `operation_id`/`idempotency_key` 去重提交。

### 配对教程

1. 桌面端进入“平台联动”，启动局域网数据中枢。
2. 生成一次性配对码或二维码，确认地址、过期时间和证书指纹。
3. 手机/网页端连接同一 Wi-Fi，打开工作台并填写主机地址。
4. 用户核对证书指纹后发送配对请求。
5. 桌面端确认设备名称和请求，令牌只交付一次。
6. 设备出现在授权列表后，可以暂停、恢复或撤销。
7. 同字段冲突进入冲突收件箱，人工选择后才写回主机。

许可证只保存在正式授权的 Electron 主机安全存储中；手机和网页端使用工作区配对令牌，不复制许可证私钥。三端共享的是业务工作区，不是三份相互独立的数据库。单文件离线 HTML 只能作为受限伴侣，不能宣称和 Electron 一样具备强授权边界。

## 更新和数据保留

桌面端的真实操作只有：点击“检查更新” → 点击“下载更新” → 等待校验 → 点击“安装并重启”。更新前自动创建恢复点；更新包校验清单签名、SHA-256 和平台签名；安装失败保留旧版本、恢复点和修复入口。SQLite、附件仓、工作区路径和配对设备不随安装目录删除。

网页在线版通过刷新获取新版本；单文件离线版需要重新下载。浏览器关闭时不能后台执行文件备份或替换，这是平台限制。用户应在导入新离线文件前导出恢复包。

许可证更新权益只影响功能版本访问，不影响安全修复和严重数据修复。许可证、设备令牌和模型 Key 不进入业务备份、学生导出和手机交换包。

## 最小安全规则

- 不使用一个所有人共用的万能 Key。
- 不把激活码、私钥、模型 Key、订单令牌写进 Git、公开网盘、学生备份或普通日志。
- 不信任客户端“已支付”参数，支付结果只来自验证过的服务端回调或受控管理员确认。
- 不让手机和网页直接访问 SQLite 文件。
- 不把 Cloud Studio、链动小铺或百度网盘当作授权私钥保险箱。
- 不把自动化契约测试写成真实支付、真实签名、真实设备已经验证。
