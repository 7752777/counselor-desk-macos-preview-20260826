# 交互连续性与按钮闭环审计（2026-08-20）

更新时间：2026-08-20  
工作分支：`codex/ai-upgrade`  
历史发布基线：`v4.7.0`  
当前状态：当前候选未发布

## 本轮目标

本轮从实际使用路径检查按钮是否真正完成下一步工作，而不只检查页面上是否存在按钮。重点是：

- 保存、确认、转换和删除是否有明确结果；
- 重复点击、刷新后再次点击是否会重复造数据；
- 业务记录能否回到来源记录；
- 异步保存失败后是否仍可重试；
- 表单选项契约是否与公共 `ui.form()` 组件一致；
- 空缺、待确认和来源变化等状态是否能被真实表达。

## 已落地修复

### 1. 实用工具结果

每次生成的抽签、分组、轮值、日期或名单清理结果现在获得当前会话内稳定的 `result_id`。保存为任务或工作留痕时分别写入来源类型/来源集合和来源 ID：

- 任务：`source_type: utility_result`、`source_id: result_id`；
- 工作留痕：`source_collection: utility_result`、`source_id: result_id`。

再次点击保存会找到同一来源并提示“不会重复创建”，结果区按钮会显示“已保存为任务/已保存为留痕”。重新生成结果才会产生新的结果 ID。工具仍默认不落库，AI 不参与随机数决定。

### 2. 科研阶段任务

科研阶段任务使用确定性 ID `research_stage_<project_id>_<stage>`，并保存：

- `source_type: research_stage`；
- `source_collection: v4_research_projects`；
- `source_id: project_id`；
- `source_stage: current_stage`。

生成前同时按确定性任务 ID和项目/阶段来源键检查。项目进入下一阶段后允许生成下一阶段任务；同一阶段重复点击不会新增任务。旧任务如果已经带确定性 ID仍可被识别，避免升级后重复创建。

### 3. 公共任务来源字段

`normTask()`现在持久化 `source_id`、`source_collection` 和 `source_stage`。这些字段不影响旧任务读取，但让任务完成、科研阶段、工具结果和 AI 转任务都可以沿来源回链。未来新增“从记录生成任务”入口必须使用稳定来源键，不得只依赖标题或当前日期去重。

### 4. 学生选项与表单组件

班委任职、班委考核、家校联系、查寝异常、量化积分和竞赛报名的学生选择器统一使用 `{ v, n }` 选项数组，与 `ui.form()` 的公共契约一致。`ui.form()`同时对历史遗留的 `<option>` 字符串做兼容解析，避免单个表单因选项类型错误直接中断。

### 5. 班委任职状态

- “在任”“代理”等有实际任职关系的状态必须关联学生；
- “空缺”允许不关联学生，用于表达岗位尚未补齐；
- 同一学生在重叠任期内不能重复担任同一角色；不同角色仍允许一人多职；
- 自定义角色名称重复时直接提示，避免角色字典出现两个看似相同的入口。

### 6. 附件失败、删除和来源生命周期

- 家校联系、科研阶段和调宿等带附件的保存流程采用“先写附件、再写业务记录、失败回滚”顺序；业务记录写入失败时不会留下无法引用的附件。
- 删除带附件的业务记录前会检查同一附件是否仍被其他记录引用；只清理确认后的孤儿附件，并保留删除审计，不误删共享证书或照片。
- 删除或作废来源记录后，关联的 `v4_worklog_drafts` 会标记为来源已删除，不能继续确认成正式留痕；来源被编辑后会标记为来源已变化，必须重新打开、核对并刷新来源哈希。
- 任何保存失败都会保留表单和附件选择状态，显示可理解的中文错误，允许修正后再次提交；不会因为弹窗关闭而丢失未提交输入。

### 7. 上下文面板和桌面端模式

- 右侧上下文面板打开时将焦点移入面板，按 `Escape` 或关闭按钮关闭后把焦点还给触发按钮；刷新后仍恢复用户上一次的展开状态。
- 上下文面板的 `aria-expanded`、`aria-hidden` 和关闭按钮状态随真实可见性同步，避免键盘用户进入不可见内容。
- Electron 学生台账的表格、卡片、照片三种模式共用同一持久化设置；卡片模式刷新/重启后仍可显示照片、班级、宿舍、导师、班主任和家长关系，电话继续默认脱敏。

## 交互规则

1. 只读统计块使用 `div[role=status]`，只有确实能跳转或执行动作的统计项才使用 `button`。
2. 动态动作按钮统一带 `type="button"`，异步动作通过 `aria-busy` 和禁用状态防止重复触发。
3. 公共表单保存按钮在保存期间显示“保存中…”，失败时保留弹窗和用户输入，允许修正后重试。
4. 删除、作废和敏感查看必须二次确认；删除来源后，关联工作记录草稿标记为来源已删除，不能用旧草稿补写正式事实。
5. 生成建议、通知、点名、排宿预览和工具结果与正式写入分离；人工确认之前不修改学生事实、考勤、住宿位置、班委等级或奖惩结论。
6. 编辑来源记录后，已有工作留痕草稿必须重新计算来源哈希；来源仍存在时由老师明确核对后才能归档。
7. 移动端只保留当前页面的主操作和必要次操作；表格在自己的滚动区域内横向滚动，按钮不得因换行被遮挡。

## 2026-08-21 保存队列与来源草稿跨集合一致性

本轮继续从“按钮点击后是否真的完成”反查保存链，补齐了此前容易在异步环境中丢失的两类状态：

- `save()` 现在把同步桥返回的 Promise 纳入串行保存队列，并通过 `awaitTrackedSave()` 将 `{ ok:false }` 转换为可重试错误；前一次失败不会污染下一次保存，确认弹窗和表单会保留在当前页面。
- 基础集合（任务、谈话、学生等）发生变化并使 `v4_worklog_drafts` 过期时，会同时同步 `custom` 集合到 v8 工作区，而不是只写旧兼容存储。
- 删除前显式标记来源草稿过期时，会登记待同步版本；只有基础记录和草稿都成功保存后才清除标记，保存失败时重试仍会带上草稿变化。
- 工作记录来源指纹覆盖备注、查课/查寝情况、处理措施、地点、优先级和截止日期等事实字段，刻意不把基础保存过程批量刷新的 `updated_at` 当作业务变化。修改这些事实字段后，草稿会进入“来源已变化”，不能继续把旧内容当作新事实归档。

交互回归新增了 v8 工作区状态断言：来源修改后的草稿和来源删除后的草稿，不仅在页面内存中显示为过期，也必须在 `CWB.workspace.getState().custom.v4_worklog_drafts` 中保持对应状态。前一个删除事务完成后，测试等待真实确认弹窗关闭，再开始下一个动作，避免固定短延时掩盖跨弹窗串扰。

## 2026-08-21 AI 按钮可用性闭环

AI 按钮的连续路径现在是“选择模型/用途 → readiness 预检 → 必要时一次性敏感授权 → 请求前二次校验 → 成功生成草稿或建议 → 人工确认转化”。模型未配置、未启用、缺少模型名、用途未授权、视觉能力不足、当前会话无密钥或额度用尽时，生成按钮会在点击前禁用并保留“添加模型/配置当前模型”入口；公共运行 API 仍会拒绝不满足条件的请求。

每日额度按模型连接和用途隔离，连接测试、失败、取消、本地通知预览不消耗额度。该规则避免多个 provider 之间互相影响，也避免老师把“模型已启用”误认为“当前会话可调用”。详细数据字段和兼容策略见[AI 模型可用性审计](./ai-provider-readiness-audit-2026-08-21.md)。

## 2026-08-21 待确认留痕的失败回滚

本轮继续检查工作记录草稿的确认和驳回按钮。两条动作现在都等待实际保存 Promise：

- 页面持久化确认失败时恢复草稿的原始状态和正式工作留痕数组，不留下“已确认但没有正式记录”的半完成状态；恢复保存后只保留一条以 `source_draft_id` 关联的正式留痕。旧的同步 `CWB.worklogDrafts.confirm()` 仍保留兼容语义，等待落盘的页面动作使用 `confirmAsync()`。
- 页面持久化驳回失败时恢复 `draft` 状态，老师仍能从原弹窗/重试入口继续处理；保存成功后才标记为 `dismissed`。旧的同步 `dismiss()` 保留兼容语义，页面动作使用 `dismissAsync()`。
- `dismissDraft` 对没有 `awaitTrackedSave` 的轻量运行环境提供直接 Promise 兜底，避免候选脚本在非完整页面夹具中因辅助函数缺失而中断。
- 同一来源已经确认的草稿按既有幂等规则复用，测试夹具也明确区分“重复确认”和“新来源驳回”两个场景。
