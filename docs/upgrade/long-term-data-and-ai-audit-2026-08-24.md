# 长期使用数据联动与 AI 语音链路审计

日期：2026-08-24  
范围：学生主档案长期更新、跨模块关联、历史兼容、录音转写、AI 配置与失败反馈。  
版本边界：当前为 v4.9.0 工作区候选；正式维护版本仍为 v4.8.5。

## 结论先行

这次审计确认，学生业务记录的正确关系应当是“学生主档案保存当前事实，业务记录保存发生当时的快照”。修改姓名、班级、导师、宿舍或学号时，不能通过重新建人、按姓名覆盖或改写历史过程记录来实现“同步”。现在的主流程已统一为稳定 `student_id` 关联，当前学号只作为快照，旧学号进入历史列表；无法唯一确认的旧记录不自动合并。

录音功能此前并非完全没有调用链：浏览器通过 `MediaRecorder` 采集 `audio/webm` 或 `audio/mp4`，前端通过 `multipart/form-data` 或受保护 relay 发送到 OpenAI-compatible 的 `/audio/transcriptions`。真正的失败原因可能来自三处：中转站只提供文本聊天、转写模型未配置/不支持、浏览器录音格式被服务商拒绝。本轮将三者拆开检查，录音界面在发送前显示就绪状态，服务端 404、415、400 也有不同提示。

## 学生数据长期更新规则

### 身份优先级

1. 明确存在且唯一的 `student_id`。
2. 当前学号 `student_number`。
3. 唯一的 `student_number_history` 历史学号。
4. 无法唯一确认时进入人工核对。
5. 姓名只用于显示和人工选择，永远不作为自动匹配键。

同一个历史学号如果出现在两个学生的历史列表中，解析结果为“无法确认”，不会随机选择学生。学号变更保留原 `student_id`，并将旧学号追加到历史列表；成绩、谈话、住宿、奖惩、资助、就业、任务和 AI 草稿不会因为学号变化而重建。

### 当前值与历史事实

| 数据类型 | 学生档案变更后的处理 |
| --- | --- |
| 姓名、班级、专业、导师、班主任、宿舍 | 更新学生当前档案；关联业务记录仍以稳定 ID 读取，页面可显示当前学生上下文 |
| 业务记录中的姓名、学号、班级 | 保留发生当时的快照；新编辑或明确重绑时才更新快照 |
| 成绩、谈话、处分、奖惩、资助、心理记录 | 保留原日期、内容、等级和结果，不自动改写历史事实 |
| 任务、回访、工作留痕 | 保留来源和记录 ID；来源变化时进入重新核对/草稿失效链路 |
| 住宿分配和调宿 | 当前住宿单独更新，历史住宿轨迹不覆盖 |
| 活动参与人 | 通过 `participant_student_ids` 关联；姓名和学号只是导出快照 |
| 附件和照片 | 业务记录只保存附件 ID；更换照片不删除仍被其他记录引用的附件 |

学生档案编辑在确认保存前展示变更字段、关联模块和关联记录数量，说明历史过程事实不会被改写。保存成功后再次提示旧快照记录数量，提醒老师补齐历史 `student_id`。这解决了“改了一个人，其他模块到底会不会跟着乱”的长期使用疑虑。

## 导入与补录

成绩期末补录可以使用只有“学号、姓名、分数”的文件。学生导入预览按当前学号更新，缺少培养层次等未出现在文件中的字段会保留；空白只有在显式选择清空空值时才会覆盖。按课程、学期保存的多门成绩仍应进入成绩管理，不把所有成绩压缩成学生档案的单一字段。

每次导入应关注四类结果：更新已有、创建新增、同文件冲突、人工核对。覆盖导入前必须确认文件是完整名单并创建恢复点；合并导入不因源文件缺少某学生而删除学生。旧记录若只有姓名或无法唯一解析的学号，保留原数据并列入后续核对，不静默合并。

## AI 语音真实链路

### 发送前检查

语音转写现在要求当前连接同时满足：

- OpenAI-compatible 协议；
- 明确勾选“服务商支持音频转写”；
- 填写独立的“语音转写模型”，不能把文本聊天模型当作转写模型；
- `voice_transcription` 在允许用途中；
- 当前工作区已激活 AI 权益且本机有模型密钥；
- 浏览器支持 `MediaRecorder`，且实际 MIME 在支持列表内。

聊天模型支持文本，不代表它支持音频。Anthropic、Gemini 或自定义中转是否能转写，不能凭名称推断，必须以服务商实际提供的音频端点和模型说明为准。

### 失败诊断

| 现象 | 诊断含义 | 使用者处理 |
| --- | --- | --- |
| 未声明语音转写 | 当前连接只有文本能力或未完成配置 | 填写独立转写模型并确认服务商支持 |
| 协议不支持 | 当前协议没有统一音频转写适配 | 改用提供 `/audio/transcriptions` 的 OpenAI-compatible 服务 |
| 404 | 中转地址没有音频转写端点 | 检查服务商路径；文本 `/chat` 能通不代表录音能通 |
| 415 | 服务商拒绝 `webm/mp4` 等当前格式 | 按服务商支持格式重录或更换转码/STT 服务 |
| 400 | 模型名、音频内容、额度或请求参数被拒绝 | 检查转写模型名、大小、格式和额度 |
| 超时/断网 | 请求未完成 | 录音不落库，保留错误提示，恢复网络后重新授权发送 |

浏览器只负责采集和临时持有 Blob，不默认把原音频写入附件仓。取消、失败、关闭窗口和完成转写后都会释放本次音频；心理记录必须经过一次性授权、人工编辑和确认后才写入事实台账。

### 长期使用检查清单

以后新增或修改一个按钮，必须回答四个问题：

1. 它写入哪些集合、附件或反向引用？
2. 成功提示是否等待全部持久化 Promise 完成？
3. 任一部分失败时，哪些内存记录、附件和草稿需要恢复？
4. 刷新、重启、同步和导出时，用户能否看到真实状态而不是临时状态？

本轮已将这些问题落实到照片、班团任职和就业资源高频路径；其他低频页面仍按同一事务辅助函数逐批收口，不把“测试通过一次”视为长期维护完成。

- 任务表单现在使用 `tasks + custom` 快照：新建、编辑和完成任务时，任务与待确认工作留痕草稿一起等待真实保存；失败会恢复原任务/草稿，表单保持打开，重试不会重复新建。
- 谈话表单现在将 `talks + tasks + custom` 纳入同一恢复边界。谈话、由跟进日期生成的回访任务、回访闭环和工作留痕草稿必须全部写入成功后才提示成功。
- 完成回访时，回访结果、当前任务完成状态、下一次回访任务和来源草稿一起保存；保存失败不会出现“谈话已完成但待办没有更新”的半成功状态。
- 删除回访任务会清除谈话上的失效任务引用并把谈话标为“待重新安排”；删除谈话会保留原回访任务，但解除来源关联并提示人工确认，避免删除过程丢失后续工作。
- 通用单条删除恢复路径现在会在失败后等待恢复写入完成，确认框不会在恢复尚未完成时结束。

本批加强 `tests/interaction-continuity.js` 的任务表单、谈话表单、回访任务和删除反向关联断言；最终通过 `node tests/interaction-continuity.js`。测试夹具中把“填写回访日期”作为创建回访任务的前置条件，符合真实业务规则。

平台任务拉取也改为等待本地任务集合真实保存后才返回新增数量，避免网络接口成功而本地写入尚未完成时用户立即切换页面造成误判。

## 2026-08-24 旧记录稳定关联维护入口

长期使用中，早期录入的谈话、成绩、住宿、奖惩、资助、就业和其他业务记录可能只有学号或姓名快照。此前系统已经能在读取时拒绝歧义历史学号，但缺少让老师逐步修复这些旧关系的工作入口。本批新增“学生关联维护”：

- 学生台账的“维护旧关联”会扫描高频基础集合和住宿、班委、家校联系、量化积分、竞赛、就业等扩展集合。
- 有效 `student_id` 的记录不进入队列。缺少稳定 ID、失效 ID、重复当前/历史学号、只有姓名和完全缺少身份信息的记录会分开标注原因。
- 当前学号或唯一历史学号只作为候选依据；仅姓名的记录始终要求老师重新检索并选择，不会自动绑定。
- 老师必须打开确认窗口、选择当前学生并勾选人工核对后，系统才补写 `student_id`。默认只在原记录缺少时补齐学号、姓名和班级快照，不改写已有的成绩、日期、谈话内容、处分、资助、住宿轨迹或其他历史事实。
- 每次确认会写入 `v4_student_identity_conflicts` 的本机处理记录，包含原关联、确认后的稳定 ID、时间和本机操作者；业务保存和该处理记录使用同一恢复边界，任何写入失败都会恢复原记录。
- 页面最多渲染 500 条待处理行，提醒先按业务来源筛选，避免大工作区一次性打开全部历史积压造成卡顿。

这不是后台数据清洗，也不把“姓名相同”变成身份认证。活动参与人数组、纯班级级记录和旧附件没有被这个入口静默改写，仍需进入对应业务模块按事实核对。

### 录音为何不能只靠聊天模型

录音不会因为“文本聊天能回复”就自动可用。当前实现已经具备浏览器采集和协议转发，不缺一个通用解析库：`MediaRecorder` 产生真实 WebM/MP4 Blob，应用以 `multipart/form-data` 发送给服务商 `/audio/transcriptions`，或通过 relay 的 `/api/ai/transcribe` 安全转发。文字识别由服务商实际提供的独立转写模型完成。

用户首次配置须依次确认：AI 增强授权、OpenAI-compatible 协议、独立 `transcriptionModel`、`supportsAudioTranscription` 声明、语音用途授权、可用密钥、服务商额度和浏览器实际 MIME。设置页的“检查语音”发送本机生成的静音 WAV，只验证端点/模型/凭据；录音窗口的“检查本机格式”生成无谈话内容的实际浏览器容器，验证服务商是否接受 WebM 或 MP4。两项都不保存音频，也都不等同于普通话、方言、长录音或手机端的转写质量验收。

错误含义保持可行动：`404` 为服务商或 relay 没有音频端点，`415` 为当前录音容器被拒绝，`400` 多为转写模型名、额度或参数问题。目标中转站若只实现文本聊天，界面会阻止真实录音发送并提示切换明确支持 STT 的服务；不能通过修改扩展名或把聊天模型名称填进转写字段来绕过。
