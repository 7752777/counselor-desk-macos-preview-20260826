# v4.6.0 日常工作与业务协同审计

更新时间：2026-08-19

本页记录 v4.6.0 对下一轮一线使用反馈的实现范围、数据边界、跨端影响和验收要求。它是长期维护文档，不把“页面出现”当作“业务闭环完成”。正式发布状态以[ v4.6.0 发布收尾记录](./release-v4.6.0.md)和 GitHub Release 实际内容为准。

## 本轮目标

v4.5.0 已经收口学生档案、通讯录、课表、活动附件、团员发展、统一导出和 AI 通知等反馈。本轮 v4.6.0 继续围绕辅导员一天中的实际动作，补齐“临时工具、住宿批次、班委履职、家长联系、科研节点、材料证据、班级分析和工作台摘要”，并修复 Electron 桌面端学生卡片模式与网页实现不一致的问题。

本批保持本地优先，不引入账号、云同步或后台读取钉钉/学校系统。旧 v4.5.0 Tag、Release 和数据格式不移动、不覆盖。

## 新增数据集合和迁移

本轮新增 10 个自定义集合：

```text
v4_dorm_buildings
v4_dorm_rooms
v4_dorm_batches
v4_dorm_assignments
v4_dorm_transfers
v4_committee_role_catalog
v4_committee_evaluations
v4_family_contacts
v4_worklog_drafts
v4_research_projects
```

工作区从 schema v8 增量标记为 v9。v8 数据仍可读取，迁移只创建缺失集合和 v4.6 设置标记，不删除旧集合、旧字段、旧学号或附件。浏览器 IndexedDB、单文件离线 HTML、Electron SQLite、备份恢复和手机交换包共用[统一集合清单](../../src/core/cwb-collections.js)。

所有学生业务关系优先使用 `student_id`。排宿、家长联系、班委考核和班级分析可以保存姓名、学号和班级快照用于历史呈现，但快照不是关联主键。附件只保存引用 ID，二进制仍由既有附件仓负责。

## 工作记录来源链

```text
业务记录
  -> source_collection + source_id + source_hash
  -> v4_worklog_drafts（待确认）
  -> 人工编辑/合并/驳回
  -> 正式工作留痕
```

业务记录被修改或删除后，草稿必须显示来源已变化，不能静默把旧摘要当成最新事实。确认工作记录只产生一次有效转化，来源 ID、学生稳定 ID 和人工确认时间保留用于回看。

## AI 边界

v4.6.0 增加 `worklog_draft`、`dorm_conflict`、`committee_evaluation_draft`、`research_checklist` 和 `class_summary` 用途。AI 可以解释冲突、整理材料、生成评价草稿、拆解阶段清单、归纳班级聚合结果，但不得自动：

- 决定床位、住宿批次或调宿结果；
- 生成或保存班委最终等级；
- 改写学生事实、奖惩结论、科研审批状态；
- 修改心理、危机、资助、纪律、预警或党团流程结论；
- 把待确认工作记录直接写成正式留痕。

默认上下文继续脱敏。当前学生、班级、学期、住宿批次、科研课题和当前事项只在明确选定的范围内进入请求；敏感字段授权只对当前请求有效，并留下用途、模型、审计编号、数据范围和人工确认状态。

## 跨端发布边界

- 源码网页加载 `src/core` 运行时；单文件构建必须将 v4.6 运行时、v9 迁移和 UI 内联。
- Electron 打包清单必须包含所有当前入口依赖，包括 `cwb-ai-workflow.js`、就业资源、导出策略、v4.6 运行时和 UI。
- Pages 构建必须复制与 `index.html` 匹配的全部外部运行时，不能只部署页面而遗漏新增脚本。
- `v4.6.*` Tag 必须触发 Release workflow；Pages 只能部署已公开、非 Draft、非 Pre-release 的 Tag。
- Windows/macOS 包是否签名、公证，必须以实际 Release 附件和 Actions 结果为准；源码通过不等于平台包已验证。

## 已知限制和后续高风险项

1. 重点学生锁仍然只是防误看，不是数据库级加密；真正加密需要独立的密钥管理、恢复策略和破坏性风险评估。
2. 浏览器 PDF 仍依赖系统打印；Electron 才提供程序化 `printToPDF`。
3. 宿舍性别限制、房间状态和学生类型只按本地录入规则校验，不替代学校住宿管理制度。
4. 班级分析缺失事实显示“未记录”，不能据此推出学生没有获奖、旷课或资助。
5. 真实 5,000 名学生、10,000 条业务记录和含证书附件的恢复流程需要在最终发布门禁中使用脱敏数据复核；本地单元测试不能替代容量实测。
6. AI 建议质量需要用学校自己的脱敏资料持续人工抽查，不用模型输出数量代替准确性。
