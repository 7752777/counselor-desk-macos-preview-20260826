# 学生增量导入、样例数据与批量操作审计

更新时间：2026-08-23

## 本轮结论

本轮不是新增一个孤立模块，而是收口三个会直接影响用户信任的细节：期末成绩能否更新已有学生、示例数据能否覆盖每个高频页面、业务档案的批量操作是否真的保存并可回退。

## 学生增量导入

当前学生身份匹配顺序为：明确匹配的 `student_id`、当前学号、历史学号；无法唯一确认的记录进入人工核对。姓名不会自动匹配。学号不再和“培养层次”拼接为复合键，因此以下文件会更新已有学生，不会新建重复学生：

```csv
学号,姓名,分数
2024001,成绩测试,91.5
```

导入规则如下：

- 只更新文件中出现的字段；缺少培养层次、班级、联系方式等列不会清空原值。
- “分数”映射到学生台账的 `academic_score` 字段，并保留数值类型。
- 空白字段默认保留原值；只有在预览中明确启用“清空空值”才清空。
- 同名但没有唯一学号或稳定 ID 时不会合并。
- 覆盖模式仍须确认源文件为完整名单，并在提交前显示删除数量和恢复点。
- 导入失败时恢复内存记录和持久化仓储；成功提示等待真实写入完成。

已增加回归覆盖：已有学生包含 `student_level`，成绩文件只含学号、姓名、分数，提交后学生数量不变且成绩更新为 `91.5`。

## 示例数据边界

首次打开仍使用脱敏示例数据。当前示例学生扩展为 16 名，覆盖两个示例班级，并为期末成绩导入保留“已有基础资料、成绩可后补”的学生记录。样例补齐到高频旧入口和新模块，首次体验不会把“暂无数据”误解为“功能未实现”。新增示例串联了：

- 住宿楼栋、房间、批次、排宿、调宿、查寝和异常；
- 课表、查课和随机点名；
- 班委岗位与考核、家校联系和待确认工作记录；
- 科研课题、阶段历史、量化规则与积分；
- 竞赛资源、报名成员、就业防骗和工具入口；
- 综合测评、学期学业、处分、资助；
- 一生一表模板与生成任务、动态分班、内容推送和工作分类。

本轮补查后，党员发展、奖惩、活动开展、成绩管理、工作留痕和学习记录也补入了首开可体验的脱敏示例，避免老入口显示为完全空白。活动参与人与成绩记录都使用现有演示学生的稳定 ID；示例附件仅展示业务字段，不伪造文件二进制。

样例记录统一带 `_demo: true`，姓名、电话、网址和附件均为脱敏或示例值，不能当作真实事实、政策依据或审计证据。系统集合不会伪造设备、同步队列、许可证、密钥、备份运行或审计凭据。

“恢复示例数据”会合并新增业务集合而不覆盖已有用户记录；“清空示例数据”会同时清理基础模块和新增 v4 集合中的示例行。学生示例使用稳定的演示 ID，重复恢复不会因引用 ID 变化而重复生成关联记录。

## 批量操作审计

已有能力：学生台账支持批量编辑、归档、删除、撤销和持久化失败回退；任务支持批量完成与删除；通用 v4 业务记录支持批量删除。

本轮补齐业务档案 `v4_assessments`、`v4_academic_terms`、`v4_disciplines` 和 `v4_aid_records`：

- 进入“批量管理”后可全选、清空和逐条勾选；桌面表格与移动卡片均可用。
- 具有状态字段的模块可批量修改状态。
- 批量删除要求二次确认，成功后才刷新；来源草稿会标记为来源已删除。
- 仓储存在时使用原子 `putMany`；失败时恢复内存和仓储的修改前快照。
- 批量操作只作用于当前集合，不删除学生基础档案和无关附件。
- 删除事务先保存记录、关联草稿和附件快照；只清理当前选择中不再被其他记录引用的附件。仓储写入失败时恢复记录、草稿和附件，失败会回到确认弹窗的重试链路，不显示成功提示。

新增 `tests/business-bulk-transaction.js` 通过真实业务页面的勾选、全选和确认操作，覆盖桌面表格排序后的稳定记录 ID、批量附件清理，以及模拟仓储失败后的业务记录/附件/草稿恢复。

仍需真实设备抽查的范围：Electron SQLite 写入失败、浏览器 IndexedDB 配额不足、附件引用清理和 5,000 名学生压力下的批量筛选。这些不能由 JSDOM 契约测试替代。

## AI 中转站核验

本轮使用固定无业务文本、1x1 空白图片和无语音 WAV 进行接口探测。用户在聊天中粘贴的 Key 未写入源码、配置、测试、日志或 Git；由于它已经暴露，验证后必须在中转平台撤销并重新生成。

探测结论：

| 能力 | 结果 | 说明 |
| --- | --- | --- |
| Responses 文本 | 可用 | `https://queqiao.online/responses` + `gpt-5.5` 返回标准 Responses 结构 |
| Chat Completions 文本 | 不可直接使用 | HTTP 200 但没有 `choices` 文本，不能把状态码当成成功 |
| Responses 视觉 | 未通过 | 该模型/中转返回 `invalid_value`，未标记为可用 |
| Responses 音频 | 未通过 | 返回“Audio input is not available”，未发送真实音频 |

产品适配器新增 `wireApi: responses`，可在 AI 模型配置中选择“Responses API（部分中转站）”。文本调用会从 `output[].content[].text` 提取结果；视觉和语音只有在服务商明确支持并通过真实配置测试后才可勾选/使用。AI 许可证、模型 API Key 和业务数据仍然是三套独立边界。

## 高频导入入口补查

本轮又对通用 CSV 预览器和三个独立导入入口进行了重复导入、空字段和失败回滚检查：

| 入口 | 默认合并键 | 已有记录 | 文件内重复 | 空字段 | 失败处理 |
| --- | --- | --- | --- | --- | --- |
| 通用业务 CSV | `record_id`；否则模块配置的自然键 | 唯一键自动更新 | 完全相同自动跳过；同键不同内容进入冲突 | 缺失字段保留原值 | 业务仓储失败回写修改前集合，保留重试入口 |
| 通讯录 | `id`；否则姓名 + 部门 | 更新原记录，不新增重复联系人 | 同一候选键只处理一次 | 空字段默认保留 | 先写仓储，失败恢复原通讯录 |
| 班级课表 | `id`；否则班级 + 学期 + 星期 + 开始节次 + 课程 | 更新原课表记录 | 同一候选键只处理一次 | 空字段默认保留 | 先写仓储，失败恢复原课表 |
| 就业资源 | `id`；否则公开 HTTPS URL | URL 相同更新原资源 | 同 URL 只处理一次 | 空字段默认保留 | 私网/非 HTTPS 地址跳过；写入失败回退 |
| 量化积分 | 稳定学生 ID + 学期 + 维度 + 方向 + 来源 | 稳定 ID 优先更新 | 同键冲突进入人工处理 | 按字段合并 | 仓储失败回退 |

通用入口不会按姓名推断学生身份；成绩文件如果目标是“学生台账增量更新”，应选择学生名单导入并使用 `学号、姓名、分数`，其中“分数”映射到 `academic_score`。如果选择“成绩管理”模块，则必须提供成绩事实所需的学期和课程等字段，不能把缺少事实字段的三列表格误当成完整成绩记录。

新增 `tests/import-merge-regression.js`，并通过 `pnpm test:import-merge` 验证：自然键更新、文件内重复行去重、同键不同内容冲突、学生三列成绩更新和通用业务仓储失败回滚。回滚时仓储可能推进内部 `rev/updated_at`，但业务字段、记录数量和新增内容均不残留，这是工作区版本协议的正常行为。

未在本轮重复运行无关的全量发布门禁；因为当前修改尚未形成正式发布候选，Windows/macOS 签名、真实 Electron 仓储、手机局域网和生产 AI 账户仍须在里程碑/发布前单独验收。用户在对话中提供的中转站 Key 已按泄露凭据处理，不进入任何测试；正式使用前必须在服务商后台撤销并重新生成。
