# 老师反馈全量审计与 v4.5.0 收口记录

更新时间：2026-08-19
对应版本：`v4.5.0`  
基线版本：`v4.4.6`

本记录把 2026-08-18 收集的 15 条一线反馈落实到源码、数据契约、测试和移动端验收。它区分“代码已经具备”“浏览器已经核对”“仍受平台或制度限制”三种事实，不把学校审批、专业判断或真实设备压测写成软件自动完成的能力。

## 收口结论

- 党员发展日期、导师/班主任、资料列表、通讯录、课表、活动参与统计、团员发展和常用栏排序已经纳入 v4.5.0 实现。
- 学生照片、家长、地址、居住类型、附件、查课查寝和导出能力已经补齐到统一业务入口；二进制附件使用附件仓，业务记录只保存附件 ID。
- 学生导入默认是“合并更新”，覆盖模式需要单独确认并先建立恢复点；更正学号不改变稳定 `student_id`，历史学号继续兼容。
- AI 通知流程已经形成“主动粘贴/导入 → 重点识别 → 草稿 → 人工确认 → 转任务或工作留痕”的边界，不后台读取钉钉、学校系统或浏览器通知。
- 移动端实际复核使用已连接的 Edge 浏览器扩展并通过响应式设备模拟；内置浏览器在本次会话没有可控标签页，因此没有把内置浏览器截图写成验收证据。

## 数据与迁移

本批新增或扩展的数据边界如下：

- 新集合：`v4_contacts`、`v4_class_schedules`、`v4_activity_participants`、`v4_league_cases`。
- 学生新增字段：`advisor_name`、`homeroom_teacher_name`、`parent_relation`、`residence_type`、`residence_address`、`landlord_phone`、`landlord_address`、`student_number_history` 及现有照片/家庭字段的完整编辑入口。
- 党团流程保留 `rule_version`、来源 URL、核验时间、节点状态和审计记录；党员旧 `party` 集合作为兼容镜像，不删除历史数据。
- 新集合进入浏览器 IndexedDB、Electron SQLite、单文件便携仓、备份恢复、交换包和手机工作包的统一清单。
- 学生导入默认合并更新；覆盖模式先生成恢复点，明确显示可能删除的记录数量，并支持撤销/恢复。
- 学号更正只更新当前学号和历史快照，不替换 `student_id`；跨模块记录、时间线、附件和 AI 建议继续按稳定 ID 回链。
- 图片、活动照片和业务附件不写入 `localStorage` 二进制；记录只保存附件 ID、摘要和必要元数据。附件批量写入失败时删除本批已落盘附件。

## 已知限制与后续边界

- 重点学生锁本批仍是“仅防误看，不是数据库加密”；忘记保护口令不能恢复数据，真正的数据库级加密需要独立高风险安全批次。
- 浏览器、离线 HTML 和桌面端的容量、系统打印、文件权限和安全存储能力不同；真实数据使用前仍需在目标设备做恢复抽查。
- 浏览器 PDF 通过打印 HTML 进入系统打印流程，Electron 才能使用 `printToPDF` 生成程序化 PDF。
- AI 不替代党团审批、心理专业判断、资助认定、纪律处理或危机处置；公开网页只在用户明确触发、通过 HTTPS/SSRF/大小/超时校验并显示来源后参与上下文。
- 以前在聊天或外部服务中暴露过的 API key 必须由账户持有人在服务后台撤销并轮换；本地代码不会保存或替换该密钥。
- 本记录不宣称完成 10,000 条业务记录和含真实照片附件的跨设备压力测试；这属于正式上线后的受控数据演练。
