# v4.7 UI 收口与历史需求查漏补缺审计

更新时间：2026-08-19

本页是当前工作区的综合收口记录。它把前几轮需求、实现源码、测试脚本、公开 Release 和本轮尚未发布的 UI 修改放在同一张账上，避免随着对话增长把“计划”“源码已有”“本地候选”和“公开交付”混为一谈。

## 事实范围

判断顺序固定为：当前工作区源码和测试 > 当前工作区构建配置 > 长期维护文档 > 公开 v4.7.0 Release/Pages 证据 > 用户提供的参考 PDF。参考 PDF 只证明体验目标，不证明本项目已经实现对应功能。

状态含义如下：

| 状态 | 含义 |
| --- | --- |
| 历史已发布 | 已进入 v4.7.0 Tag、Release 和当时的 Pages/构建证据；仓库私有化后 Pages 不再是当前入口 |
| 工作区候选 | 当前源码已有，但不在公开 v4.7.0，不得对用户称为已上线 |
| 部分完成 | 有可用基础，但仍缺少计划中明确的闭环、跨端或长期验证 |
| 未完成 | 当前源码和测试没有足够证据，不以文档描述替代实现 |

当前结论：公开 v4.7.0 的业务功能和参考工作台基础层已经完成；本工作区新增的首页工作台、统一视觉层、学生筛选收拢和窄屏顶栏收口属于“工作区候选”，尚未提交、推送或发布。当前公开版本没有被覆盖。首页候选又完成了一次显示层纠偏：旧版重复的“今天要处理”和 KPI 不再输出，趋势与统计改为默认收起的“数据概览”，避免一页出现两套工作台。

本页表格中的“已公开”均指历史 v4.7.0/v4.6.0 Release 当时已经交付，不表示仓库私有化后的 Pages 仍可访问；当前候选必须以本页“工作区候选”和[全量开发计划对账](./full-plan-reconciliation-2026-08-19.md)为准。

逐页功能拆分见[参考工作台功能与 UI 审计](./reference-product-feature-and-ui-audit-2026-08-19.md)。公开版本已经吸收业务结构，但以下限制仍要保留：

| 党员/处分 | 流程阶段、状态、日期、详情和导出 | 不生成审批结论，不替代组织程序 |

### 视觉规则

- 正文约 14px、行高约 1.68；页面标题约 23-25px，模块标题约 16px，表格正文约 13px。
- 页面区域按“标题/说明 -> 统计 -> 筛选 -> 主操作 -> 结果”排列。
- 页面区块使用白色内容面和 8px 左右圆角，减少层层嵌套卡片；蓝色只承载主操作和选中态，绿/黄/红表达状态。
- `>=1280px` 使用左导航、中央区、可折叠右侧区；`1024-1279px` 右侧区默认隐藏；`<=900px` 使用抽屉、单列和底部快捷栏。
- 360px 以下收缩顶部保存状态、隐藏诊断按钮，保留完整产品名和菜单入口；交互控件仍满足触摸目标高度。
- 首页只保留一套“今天要处理”主工作区，首层显示 5 个摘要和 4 个维护状态；趋势、职责、学生结构和热力图进入可展开的数据概览，避免首屏被统计长内容淹没。
