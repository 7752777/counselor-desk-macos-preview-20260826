# 用户视角综合审查：安全、可靠性与日常工作流

更新时间：2026-08-18

审查对象：已公开的 `v4.5.0` 产品，以及作为对照的 `v4.4.6` 历史基线。

本报告中的发布事实已由 [v4.5.0 发布收尾记录](./release-v4.5.0.md)回填。v4.5.0 的 Release、跨平台附件、SHA-256 清单和 Pages 均已完成；本报告列出的“仍需补强”是后续产品迭代，不代表当前 Release 未发布。

这份报告不把“代码已经存在”当作“用户已经获得价值”。判断标准是：一名真实辅导员能否在受控设备上安全地导入、查找、跟进、交接和恢复学生工作；出现误操作、设备更换、浏览器配额不足或模型失败时，系统是否给出可理解且可恢复的路径。

## 结论先行

项目已经具备实际落地所需的主干能力：本地优先数据工作区、学生与业务记录、稳定 `student_id` 关联、导入预览与回滚、附件仓、加密备份、桌面端、手机工作包、统一 AI 建议中心和公开发布链路都已形成闭环。

但它仍然不能被描述为“数据天然加密”或“自动替代人工判断”。当前最重要的边界有四个：

1. 重点学生档案的 4 位口令是防误看锁，不是数据库加密；忘记口令只能清除界面限制，不能恢复口令或保护底层数据。
2. 浏览器网页端只能手动生成加密备份；按时间或变更量自动落盘的备份能力属于桌面端，并且需要配置受控目录和备份口令。
3. 浏览器容量取决于具体浏览器、设备和 WebView 配额。附件已迁移到 IndexedDB/桌面仓储，但这不等于空间无限；达到阈值时应先备份、清理和重试。
4. AI 只生成建议、草稿和可审核的转化记录，不自动修改心理、危机、预警、纪律、资助、奖惩或学生事实；此前在聊天或配置中暴露过的 API key 必须由账户持有人撤销并重新生成。

## 我作为使用者最期待的体验

### 1. 打开就知道现在是否安全

首页应该直接告诉我三件事：当前工作台是否上锁、最近一次加密备份距今多久、备份后发生了多少条变更。当前版本已经显示备份新鲜度和容量风险；下一步应让“未生成加密备份”成为醒目的初始化任务，而不是藏在设置里。

我不会把“本地保存”理解成“不会丢”和“已经加密”。产品文案必须继续明确区分：

- 防误看锁：阻止普通界面查看，不能阻止技术人员读取浏览器存储。
- 工作台访问锁：控制进入页面和敏感操作，不能加密数据库。
- 加密备份：口令正确才能恢复，忘记口令不可恢复。
- 系统/磁盘加密：由操作系统和设备管理负责。

### 2. 每个危险操作都给我退路

批量删除、覆盖恢复、手机回传覆盖、清除口令、导出完整档案和清空工作区都应在动作前告诉我影响范围、是否可撤销、是否先生成快照。当前已有多处二次确认、恢复点和导入回滚；后续应把“恢复点已创建”显示在确认流程内，而不只在后台完成。

### 3. 我不想等，也不想猜

大名单导入、附件写入、备份加密和 AI 请求都应显示进行中、成功、失败、取消和可重试状态。失败时要告诉我“数据有没有写进去”，而不是只说“操作失败”。当前导入任务、AI 取消/重试、容量拒写和备份错误码已覆盖主要路径；需要持续防止异步动作在页面刷新后留下假性的“进行中”。

### 4. 我希望围绕一个学生完成工作

最自然的动作不是先想“我要去哪个模块”，而是打开一个学生后看到：基本资料、近期成绩与考勤、谈话和回访、奖惩与资助、心理/重点关注、就业意向、附件、当前任务和历史时间线。AI 也应从当前学生和当前事项出发，给出会前 briefing、缺项提醒和下一步草稿，而不是把我重新送回一个空白聊天窗口。

### 5. AI 要帮我省步骤，不要替我下结论

我期待 AI 能把散落记录整理成“我下一步可以做什么”，并且每条建议能回到来源、学生和时间范围。我不接受模型直接把推测写进心理、危机、纪律、资助或学生事实。当前建议中心和来源状态已经提供了这个边界；下一轮应继续提升真实业务资料下的请求内容、来源片段和人工复核体验。

## 分层风险与改进清单

### P0：发布前必须守住的边界

- 保持“防误看锁，不是加密”文案；清除口令的按钮必须明确“不恢复口令”，且启用了工作台访问锁时再次验证。
- 敏感导出默认经过字段预览、工作台访问锁和审计；平台联动桥默认只输出脱敏最小视图，心理、资助、重点档案等高敏感集合默认排除。
- 浏览器和桌面端都要显示备份新鲜度；业务变更递增计数，桌面端按周期或变更阈值触发，网页端明确显示“仅支持手动备份”。
- 照片和附件走 IndexedDB/桌面仓储，不再把二进制塞入 `localStorage`；容量检查至少覆盖 `navigator.storage.estimate()`、兼容存储和附件大小。
- 继续扫描源码、文档、备份、日志和发布产物中的真实凭据；此前公开的外部 API key 不得因为扫描通过而被视为已撤销。

### P1：最贴近一线工作的补强

- 学生档案继续补齐全维时间线：成绩、考勤、谈话、奖惩、资助、心理、就业、任务、附件和回访均用稳定 `student_id` 回链。
- 谈话保存回访日期时，确保下一次任务或提醒真正落库，并支持完成、顺延和关闭；不能只显示一句建议。
- 工作留痕继续补充学校定制的月度、学期汇报模板；现有统一导出已支持 DOCX、打印 HTML 和 Electron PDF，仍需持续验证模板、来源、字段脱敏和人工确认边界。
- 增加家校沟通台账：家长关系、联系方式、家访/家长会记录、签到和学生双向关联；默认不出现在普通统计或平台交换包。
- 建立 AI 建议中心的移动端批量查看、来源回链和转化状态；高风险结果继续禁止批量采纳。

### P2：通用化与长期维护

- 增加字典/配置中心，让学校管理员维护荣誉类型、政治面貌、毕业年份、关注分类、职责和政策标签；代码只提供默认值和迁移规则。
- 导航按学校职责分组，同时保留搜索、置顶和恢复；分组名称应允许配置，不把单一学校术语写死为唯一答案。
- 对大数据量建立真实浏览器基准：1 万、3 万、5 万学生，附件 100 MB、500 MB、1 GB，比较首次加载、筛选、保存、备份和恢复时间。
- 继续拆分源码和依赖的维护边界；正式交付仍可生成单文件，但每个 vendor 必须有版本、来源、许可证和升级验证记录。
- 桌面端补齐系统安全存储、请求取消、失败重试、用量统计、代码签名和 macOS 公证的生产配置。

## 兼容性与性能判断

### 浏览器与设备

- 在线 Pages 适合体验和脱敏数据；真实学生资料优先放在受控桌面端或受控离线包中。
- 单文件 HTML 适合携带，但浏览器对 `file://`、IndexedDB、下载权限和配额的实现不同；重要数据必须先做恢复演练。
- 手机的 `127.0.0.1` 是手机自己，不是电脑；电脑开发服务应使用同一局域网 IP，或直接使用 Pages/离线文件。
- 当前已对 `390×844` 和 `360×800` 进行移动导航和无横向溢出复核；仍应在目标学校实际手机浏览器上确认文件选择、下载、IndexedDB 和返回行为。

### 本地缓存与响应速度

- 学生台账的筛选、排序和派生结果已经缓存复用，5,000 条组合筛选性能回归通过。
- 业务主记录仍有兼容 `localStorage` 路径，附件和较大集合走 IndexedDB；因此“localStorage 上限”没有消失，只是高风险二进制不再主动占用它。
- 容量仪表盘是风险提示，不是浏览器配额的精确承诺；达到 70% 关注、85% 阻止高风险大写入、95% 进入危险状态后，应优先备份和清理。
- 后续性能验证应记录真实机器和浏览器，不把 jsdom 或开发机结果包装成所有设备都能达到的响应时间。

## 验收标准

| 验收项 | 通过条件 |
| --- | --- |
| 防误看锁 | 文案明确非加密；忘记口令只能清除界面限制；工作台锁启用时需要再次验证；有审计记录 |
| 敏感导出 | 默认最小字段；敏感字段有预览和确认；平台交换包不含高敏感原文；审计页可检索 |
| 备份 | 首页显示距离和变更数；网页手动备份边界明确；桌面计划可按时间/变更量触发；恢复前有回退点 |
| 容量 | 附件写入前检查增量；容量页显示附件数量和大小；配额不足时不写半条记录 |
| AI | 默认脱敏；敏感授权只对一次请求有效；建议带模型、用途、来源和学生稳定 ID；事实记录不自动改变 |
| 移动 | 首次打开可直接打开菜单；抽屉可用搜索、分组、遮罩、Escape 和返回键关闭；无横向溢出 |
| 迁移 | 浏览器、单文件、Electron、备份恢复和手机包保留稳定 ID、附件引用和历史学号 |
| 发布 | Tag、源码、Release、Pages、离线包和校验清单来自同一提交；未签名/未公证状态明确写出 |

## 当前未完成，不能提前宣称

- 真正的数据库级加密存储和忘记口令不可恢复方案尚未实现；当前交付的是明确标注边界的界面锁和加密备份。
- 家校沟通独立模块、字典/配置中心、学校定制汇报模板和更大规模真实设备压测尚未完成；通用 DOCX、打印 HTML 和 Electron PDF 导出已经完成并随 v4.5.0 发布。
- AI 专属指令在真实学校资料上的准确性、遗漏率和人工接受率仍需持续评估。
- 外部 API key 的撤销和轮换需要账户持有人在服务后台完成，代码不能代替该操作。
- Windows/macOS 公开包未配置代码签名，macOS 未公证；这不是测试通过可以消除的限制。

## 下一轮执行顺序

1. 以已公开的 `v4.5.0` 为稳定基线，使用真实脱敏数据继续做安全、备份、容量和兼容性验收；本版本的公开面门禁已完成。
2. 以真实脱敏数据做学生档案、谈话回访、工作汇报和 AI 建议的人工验收。
3. 再做家校沟通、字典配置和 Word/PDF 输出，避免把未完成能力混入当前发布事实。
4. 建立大规模数据和附件性能基线，再决定是否需要进一步拆分运行库或调整默认分页。
5. 最后推进签名、公证和学校部署清单，形成可交接的生产运维文档。
