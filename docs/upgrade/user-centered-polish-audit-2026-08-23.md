# 使用者视角持续打磨审计（2026-08-23）

## 本轮目标

本轮不新增孤立模块，集中改善首次上手、首页决策、按钮反馈和 AI 状态提示。原则是让用户在每次点击后都能知道：当前发生了什么、数据是否已经保存、失败后怎么继续。

## 已落地

### 1. 首次使用路径

- 首页首次使用卡片改为三步可执行路径：设置个人信息、导入真实名单、完成首次加密备份。
- 每一步显示完成状态、下一步说明和直接入口；不再把“正式初始化”统一送到设置页后让用户自行寻找。
- 用户不需要一次录完所有字段。页面明确提示成绩、谈话和业务记录可以在后续工作中逐步补齐，符合开学先录基础信息、期末再导入成绩的实际流程。
- 保留功能导览、示例体验、从备份恢复和暂时跳过；移动端使用纵向步骤，不压缩成拥挤的横向按钮组。

### 2. 空状态

- `emptyBox` 支持状态语义、下一步说明和操作按钮的统一包装。
- 现有模块继续提供“新增第一条”“从 CSV 导入”等真实入口，避免空白页面只显示“暂无数据”。
- 空状态使用 `role=status` 和 `aria-live`，筛选后没有结果时不会让屏幕阅读器失去上下文。

### 3. 保存失败和恢复

- 表单保存仍保留输入内容，保存按钮进入“保存中”状态，成功后才关闭弹窗。
- 保存失败继续保留重试按钮和待恢复状态；数据没有确认落盘时不显示成功提示。
- 通用错误提示优先使用稳定错误码翻译为用户语言，避免直接显示 `LICENSE_REQUIRED:...`、`STORAGE_WRITE_FAILED` 等内部字符串。
- 增加工作区损坏、仓储解密失败、AI 授权未激活、模型未配置和 API Key 缺失的明确下一步提示。

### 4. AI 当前状态

- 商业模式下，未激活 AI 许可证显示“功能已锁定”和“激活 AI 授权”；不再与“没有配置模型”混为一类。
- 有许可证但未配置模型时显示模型配置入口；有模型但没有密钥时显示密钥配置入口。
- AI 请求仍经过统一授权层和模型就绪检查，未授权不会发出模型请求；结果仍只能生成建议或草稿，不能自动修改事实。
- AI 错误提示保留重试路径，同时不把完整请求、密钥或敏感学生字段写入普通日志。

### 5. 学生台账导入与期末补录

- 学生台账新增“开学先建档，后续资料可以继续补充”引导条，把“导入名单 / 更新”和“录入课程成绩”分成两个直接入口。
- 导入预览对学生记录改用使用者语言显示“更新已有记录 / 新增记录 / 需要人工核对”，并在行内展示实际身份匹配依据和实际写入字段。
- 当前预览明确显示稳定学生 ID、当前学号、历史学号的匹配顺序；姓名不会自动匹配，无法唯一确认的记录必须人工处理。
- 空白字段默认保留已有值；只有明确开启“清空空值”才会清空字段。合并更新不会因文件缺少学生而删除已有档案，覆盖导入仍要求完整名单确认和恢复点。
- 期末常见的“学号、姓名、分数”三列表格会按当前学号更新已有学生的综合成绩，不会因为缺少培养层次而重复创建档案。需要按课程和学期保存多门成绩时，页面引导进入成绩管理。

### 6. 首页信息密度与示例数据切换

- 首页“今天要处理”严格只渲染按优先级排序后的前 5 条，超过部分通过“查看其余”进入完整任务列表，不再因为回访事项被追加而拉成长页面。
- 示例数据提示现在把“导入真实名单”作为主要动作，把“清空示例数据”降为次级操作；用户可以先体验再进入真实数据流程，不需要先执行破坏性清空。
- 首页“数据与维护”保留五项紧凑状态，详细的备份、同步、冲突、照片和导入状态继续默认折叠；折叠状态按工作区 UI 状态保存。

### 7. UI 状态持久化与高频操作连续性

- 首页折叠、路由切换等轻量 UI 状态先写入本地 UI 状态，再以 40ms 合并窗口排队写入 v8 工作区设置；连续点击不会为每次导航创建独立的工作区写入。
- 合并写入仍使用最新状态，写入失败沿用统一工作区错误提示和恢复入口；业务记录保存不依赖 UI 状态写入完成。
- 修复了“首页展开维护详情后进入其他页面，再执行通知本地预览需要等待多次 UI 状态写入”的可感知延迟。

- 就业意向、就业联系和业务档案新增表单统一显示“请选择学生”占位；保存时从当前下拉框重新解析学生，并同步写入稳定 `student_id` 与当前学号快照，避免新增记录默认挂到名单第一人或沿用旧上下文。

### 8. 学生关联和失败重试继续收口

- 请假、考勤、学业预警、学业帮扶、奖助勤补、重点学生、心理摸排、毕业生档案、校外住宿、假期去向和评优申报等传统表单现在统一按“稳定 `student_id` → 当前学号快照”保存；姓名只作为可读快照，不再承担唯一关联职责。
- 成绩、奖惩、活动和工作留痕等 v4 记录表单补充学生选择下拉，编辑时回读当前学生，保存前再次解析当前选择；姓名与学号不一致时留在表单内提示修正，不静默写入错误学生。
- 传统表单保存改为事务式流程：先修改内存、等待真实仓储保存成功，再关闭弹窗和显示成功提示；失败时恢复原数组并保留表单，重试不会重复新增。编辑记录恢复时保留原对象引用，避免第二次点击重试失去编辑目标。
- 这批改动没有新增数据集合或迁移，旧的姓名、学号和自由文本字段继续保留，能够从旧记录逐步补齐稳定 ID。

## 未扩大承诺的事项

- 本地构建产物在本轮可视化浏览器中被本地文件 URL 安全策略拦截，因此没有把截图验收结果伪装成已完成；需要在实际桌面端、HTTP 预览服务和真实手机视口继续检查。
- Windows/macOS 签名、公证、真实支付、KMS、生产授权服务、客户下载 CDN 和多设备实机同步仍不因本轮 UI 改动而视为完成。
- 本轮没有新增数据迁移、没有更改历史 Tag/Release，也没有执行与当前代码状态无关的全量测试和完整发布构建。
