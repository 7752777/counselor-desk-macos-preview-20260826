# v4.8.5 基线与 v4.9.0 商业化前审计

日期：2026-08-23

## 结论

`v4.8.5` 仍是最后一个正式 Tag/Release。当前工作区版本号已提升到 `4.9.0`，但 v4.9.0 只是商业候选，不能用本机 `output/` 或工作分支替代正式客户交付物。

v4.8.5 的业务协议保持：`schema_version: 8`、`data_schema_version: 11`、`sync_protocol_version: 1`。本轮没有新增业务事实集合，也没有把许可证、设备令牌或模型 API Key 写入业务仓库。

本次审计覆盖上一轮商业授权和更新运行时修改后的当前候选代码。当前工作区的自动化门禁已经通过，但这不等于生产授权服务、平台签名、公证或真实设备更新已经完成；候选仍不能当作 v4.9.0 正式发布物。

## 尚未完成

- 生产授权服务的 PostgreSQL、KMS/HSM、管理员身份体系、限流、邮件和支付 webhook 尚未部署。
- 生产许可证公钥尚未注入商业构建；源码默认 `development`，因此不能直接把当前构建交付为商业包。
- `electron-updater` 运行依赖、清单签名契约和更新运行时已通过自动化测试；通用更新 CDN、清单发布流程、安装包签名和失败后跨重启回滚尚未在真实 Windows/macOS 设备验收。
- Windows 代码签名、macOS Developer ID 签名和公证尚未配置。
- 真实购买、退款、换机、30 天断网宽限、时钟回拨和三设备边界需要服务端与实体设备联合测试。
- 许可证服务的内存适配器仍只用于契约测试；PostgreSQL/KMS/Fastify 生产适配器已落在 v4.9.0 候选源码中，但真实数据库、密钥服务和部署环境尚未接入。

## 数据安全判断

激活码只在授权服务请求、Electron 安全存储和服务端授权数据库中出现。渲染层公开 `getState()` 已移除 token 与签名 payload；普通审计仅记录动作和非敏感状态。生产 relay 不得记录用户模型 Key、完整请求、完整响应或学生业务数据。

## 验收分层

截至 2026-08-23，当前候选已通过：`pnpm test`、`pnpm test:commercial`、`pnpm test:desktop`、`pnpm lint`、`pnpm check:public`、`pnpm check:secrets`（380 个仓库文件）、`pnpm check:docs`、`pnpm test:release` 和 `git diff --check`。`pnpm build:release` 的最终结果记录在 [v4.9.0 商业授权候选收尾记录](./release-v4.9.0.md)。

自动化通过只证明纯函数、契约、JSDOM 页面和注入式桌面运行时的边界。真实环境仍需 Windows/macOS 安装升级、签名、公证、局域网客户端、授权服务、支付、邮件、断网和恢复演练。所有这些证据齐全后，才可以把候选提升为 `v4.9.0` 正式发布。
