# 桌面端安装与数据位置

桌面端适合在固定电脑上长期维护学生资料、附件和备份。当前维护版本为 v4.8.5。下载前请先阅读 Release 说明，确认版本、平台、SHA-256、签名/公证状态和已知限制。

## v4.9.0 候选安装与数据目录

当前工作区的 v4.9.0 候选已保留自定义安装目录能力，并把许可证状态放在独立的 Electron `safeStorage` 文件中。候选包含更新状态、失败回滚、清单签名和平台签名工作流；`electron-updater` 真实 CDN、Windows/macOS 代码签名、公证和真实安装升级仍需在正式商业构建中完成。发布工作流缺少签名凭据会直接停止，不会把未签名包当作商业包；不要用本地预览文件证明这些外部能力。

锁定 AI 入口不会从键盘 Tab 顺序中消失；它使用禁用语义保留激活入口，按 Enter 或空格可以打开许可证窗口。激活状态不随业务备份迁移，换机需要重新在线绑定；更新失败时不要卸载旧版或删除数据目录，应保留恢复点和失败状态文件。

## v4.8.5 正式安装与数据目录

v4.8.5 延续 v4.8.3 的可选安装目录、独立工作区数据目录、仓储健康检查、恢复包和迁移失败回滚；本次维护不改变桌面数据目录或安装器行为，主要补强单文件 Web 资产完整性和发布门禁。升级不会删除旧工作区；升级前仍建议先导出恢复包，并将恢复口令离线保管。

## v4.8.2 历史安装与数据目录

v4.8.2 延续 v4.8.0/v4.8.1 的可选安装目录、独立工作区数据目录、仓储健康检查、恢复包和迁移失败回滚；同时修复业务仓储异步写入失败后的内存回退。升级不会删除旧工作区；升级前仍建议先导出恢复包，并将恢复口令离线保管。恢复口令至少 12 位，导出需要二次确认，错误口令不会替换当前数据。

## Windows

1. 从 Release 下载与系统架构匹配的安装包；不要从第三方网盘下载未知文件。
2. 如有 SHA-256 清单，先核验文件完整性。
3. 安装前关闭正在运行的旧版，升级前导出一份备份。
4. 首次打开后，用脱敏数据确认台账、附件与备份入口可用。
5. 卸载时按提示选择是否保留数据。默认应保留数据；确认不再需要且已完成备份后，才选择删除。

### Windows 安装前的 60 秒检查

- 确认下载页面展示的是正式 Release，而不是 Preview、草稿或聊天转发的文件。
- 选择与设备相符的 `x64` 或 `ARM64` 安装包，并核对 Release 附带的 SHA-256。
- 关闭旧版本，先导出备份；安装目录与用户数据目录不是同一个位置。
- 安装完成后先用脱敏数据验证启动、保存、附件打开、备份与退出保存，再处理唯一的正式数据。

## macOS

1. 从 Release 下载 DMG 或 ZIP；Intel 与 Apple Silicon 的具体支持以附件说明为准。
2. 未签名、未公证的体验包会被系统提示。只在确认文件来自项目 Release 且符合本校软件管理要求时继续。
3. 首次打开后，用脱敏数据测试数据目录、附件、备份恢复和退出保存。

### 关于签名与公证

是否签名、公证以及对应的系统提示，只以 Release 页面实际写明的状态为准。没有签名证书时，项目会明确说明“未签名、未公证”，不会把构建成功写成已通过 macOS 信任链验证。

## 数据目录与升级

桌面端的数据目录属于用户数据，不应随意删除、同步到公共位置或直接用文本编辑器修改。安装目录和数据目录是两回事：升级或重装前应导出备份，卸载时也应先确认数据保留选项。

v4.8.5 的 Windows x64 / ARM64 安装器及 macOS Universal DMG / ZIP 是当前下载资产；v4.8.3、v4.8.2、v4.8.1、v4.8.0、v4.7.1、v4.7.0 及更早安装器仍可从历史 Release 追溯，但不应作为当前下载入口。当前构建、安装路径、数据目录和恢复边界见[v4.8.5 发布收尾记录](./upgrade/release-v4.8.5.md)。

v4.9.0 商业候选的升级不会卸载旧版本：安装器更新程序目录，保留工作区数据目录、SQLite、WAL、附件仓和恢复点。更新前由桌面运行时创建恢复点，下载包先验清单签名、SHA-256 和平台签名；迁移失败时保留旧版本和原数据目录。许可证状态在单独的安全存储中，不能通过业务恢复包复制到新设备；换机需要在线重新激活并受设备上限约束。

v4.8.3 及更早版本是历史正式版本。当前 v4.8.5 在其基础上维护单文件离线资源完整性和发布门禁。正式下载、SHA-256 和发布证据以 [v4.8.5 Release](https://github.com/7752777/counselor-desk/releases/tag/v4.8.5) 及[发布收尾记录](./upgrade/release-v4.8.5.md)为准；Windows/macOS 未签名，macOS 未公证。

### 升级时最重要的事

1. 在旧版本仍可打开时导出备份，并确认备份文件能被找到。
2. 不手工删除原来的用户数据目录，不用“清理工具”替代迁移步骤。
3. 升级后先确认学生数量、几份附件、最近谈话和备份入口，再开始新的批量工作。
4. 若升级后看不到数据，停止继续写入，保留旧目录和备份，按问题说明提供脱敏信息。

## 遇到问题怎么办

- 打不开：确认操作系统版本、下载完整性与安全软件提示；不要先删除数据目录。
- 升级后看不到数据：停止继续写入，在旧版/旧设备导出备份后再排查。
- 附件缺失：保留原数据目录和备份文件，记录附件 ID、文件名与操作步骤后报告问题。
- 提交 Issue 时严禁上传真实学生数据、备份包、照片或完整日志。

## v4.8.0 正式安装与数据目录（历史发布）

v4.8.0 正式安装包使用根目录 `electron-builder.yml` 的 `oneClick: false` 和 `allowToChangeInstallationDirectory: true`，同时保留既有用户数据目录逻辑。`desktop/main.cjs` 提供数据目录查询、迁移前副本、迁移后 SQLite/附件健康检查和失败保留原目录；密钥 envelope、恢复口令和仓储诊断已随历史 Release 交付。

上述内容已进入 v4.8.0 正式安装包的发布范围；Windows/macOS 实机安装、自定义盘符迁移、损坏密钥、损坏 SQLite、附件回读和失败回滚仍应按发布后维护清单在目标学校设备抽查。

v4.8.0 提供 Windows/macOS 局域网主机核心和客户端管理页面。主机通过一次性配对码/二维码、HTTPS 和证书指纹接收手机、网页和其他桌面端请求，不允许客户端直接共享 SQLite 文件；配对、设备撤销、同步冲突和附件操作写入本地审计。附件分块上传/下载页面和主机加密落盘已交付，但手机真实证书信任、自动发现、断网重连、Windows/macOS 实机迁移和长期压力仍是发布后限制。详见[局域网同步与存储记录](./upgrade/lan-sync-and-storage-v4.8.0.md)。

v4.8.0 备份页还提供用户自有 HTTPS/WebDAV 加密备份连接配置、测试连接、上传、下载并预览恢复和删除。地址必须是 HTTPS，URL 不得携带账号密码；Bearer/Basic 凭据只保留在当前页面会话，不写入工作区设置。`tests/v48-cross-platform-recovery.js` 已完成浏览器、离线 HTML、加密备份、手机工作包、交换包和附件回读的脱敏契约验证，但不替代真实 Windows/macOS 安装、数据目录迁移、损坏数据库回滚或真实服务商互操作。

### 选择数据目录时的安全行为

桌面端把“程序安装目录”和“工作区数据目录”分开处理。数据目录选择器必须返回一个明确的文件夹路径；空值、磁盘根目录、当前工作区、当前工作区内部路径和已有文件会被拒绝，不会把取消选择解析成当前启动目录。迁移前会创建恢复副本，目标仓通过加密记录健康检查后才切换；切换失败会重新打开原目录，原目录也无法恢复时停止写入并提示保留恢复副本。

局域网配对信息弹窗可以复制主机 HTTPS 地址、一次性配对 ID、配对码和证书指纹；二维码只负责填充配对信息，仍需人工核对指纹和主机确认。不要把配对码、证书指纹或恢复口令发到公开群聊。v4.8.2 正式安装包继续包含该能力，真实手机信任和自动发现仍未承诺。

### v4.8.2 P0 诊断提示

桌面端会把通用 `Error invoking remote method` 转换为带 `code` 的 `CWBDesktopError`。遇到 `VAULT_KEY_DECRYPT_FAILED`、`REPOSITORY_DECRYPT_FAILED`、`ATTACHMENT_DECRYPT_FAILED` 或迁移回滚错误时，应停止继续写入，保留原数据目录和恢复包，按错误码进入数据修复向导；不要卸载后删除用户数据。v4.8.2 还要求同步队列和业务仓储的异步保存失败回滚，不把未落盘的按钮反馈当作完成。

### 二维码配对的当前状态

本文件前文“没有二维码”是历史安装说明。v4.8.2 的配对弹窗能显示二维码，并保留主机地址、配对 ID、配对码和证书指纹的复制回退。二维码内容受核心白名单约束，只包含短期配对信息；扫描后仍须人工核对证书指纹并由主机确认。自动发现、自动证书信任和真实手机扫码仍是发布后限制；正式包已包含二维码入口。

### v4.9.0 商业更新状态

商业候选的 Electron 更新不卸载旧版本。下载后先验证清单签名、SHA-256 和平台签名；Windows 使用 Authenticode，macOS 按安装包类型使用 `codesign`/`spctl`/`pkgutil`。安装前会在独立恢复目录创建快照，并写入 `vault/update-install-state.json`。如果更新器抛错、重启后仍是旧版本或新版本无法通过 SQLite/WAL/附件健康检查，桌面端会保留失败目录并切换回经过校验的恢复点；回滚失败时不要删除任一目录，也不要生成新密钥。

当前已通过注入式 `platform-signature`、`update-runtime` 和 `update-rollback` 契约测试，但本地没有真实 Windows 证书、macOS Developer ID、公证凭据或跨重启安装器证据。因此 `v4.9.0` 仍是候选，客户应使用正式 `v4.8.5` Release，除非获得受控候选包和单独的验收记录。
