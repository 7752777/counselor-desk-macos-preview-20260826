# 备份、迁移与恢复

当前工作区候选版本为 v4.9.0；正式用户仍按 v4.8.5 Release 使用。v4.9.0 的许可证、设备令牌和模型 API Key 不属于业务工作区，不进入业务备份、交换包、导出或学生数据迁移。

## v4.9.0 候选数据契约设计与发布边界

许可证状态独立保存：Electron 使用系统 `safeStorage` 加密的 `vault/license-state.bin`，浏览器伴侣使用独立命名空间。更新前必须建立现有工作区恢复点，更新失败不覆盖 SQLite、附件仓或当前有效快照。当前候选保持 `schema_version: 8`、`data_schema_version: 11`、`sync_protocol_version: 1`，不新增业务事实集合。

备份不是“出问题以后再想办法”的按钮，而是导入、覆盖、换机和交接前的标准动作。本页只说明安全的通用做法；具体菜单名称和可用格式以当前 Release 为准。

当前维护版本为 v4.8.5，延续 `schema_version: 8` 工作区协议、业务 `data_schema_version: 11` 和物理 IndexedDB v6；本次维护不新增迁移，修复单文件离线资源完整性并扩大发布门禁。换机或交接时只使用有权限访问的 v4.8.5 Release 备份/恢复说明，并以[本版本发布收尾记录](./upgrade/release-v4.8.5.md)区分当前与历史版本。

当前 AI 出站安全边界已随 v4.8.0 代码冻结：本地 `ai_request_id` 回链、学号快照范围校验、来源指纹复核和出站索引脱敏都保留；来源的 `student_number` 兼容快照只用于本地范围解析，恢复后仍不能发送给模型。完整版本对账见[全量开发计划对账](./upgrade/full-plan-reconciliation-2026-08-19.md)和[2026-08-20 AI 全面收口审计](./upgrade/ai-comprehensive-audit-2026-08-20.md)。

2026-08-20 的 AI 收口继续不增加集合、不改变 v8 工作区协议或 v10 业务迁移：直连响应上限、取消竞态、视觉协议转换、消息清洗和建议质量反馈都属于运行时/既有 `v4_ai_audit` 字段变化。恢复旧数据时没有新集合需要初始化；恢复后的建议仍应保留原有来源新鲜度和人工确认边界。

v4.8.0 为 `v4_ai_sources` 的本地目录来源补齐稳定来源 ID、业务集合/记录回链、`source_fingerprint` 和 `source_updated_at`。这些字段只用于本机来源追溯和转化前的新鲜度复核，不作为模型上下文发送；资料被修改或删除时，恢复后的建议仍必须保持“需要复核”，不能因为备份恢复绕过来源门禁。该加固不回写历史 v4.7.0 Release。

## 什么时候必须先备份

- 批量导入一份新名单或覆盖已有数据前。
- 清理浏览器、重装系统、换电脑、换浏览器或升级桌面版前。
- 交接岗位、移动资料库或删除大批量附件前。
- 要把数据交给另一位授权同事前。

## 推荐的备份习惯

1. 在工作台内生成备份，使用独立且妥善保管的口令（若版本要求口令）。
2. 为备份命名或记录日期、用途和来源，例如“2026-08-13-开学前台账”。
3. 保存到受控位置，例如学校批准的加密介质或受控网络盘；不要放进公开群、个人社交平台或不明网盘。
4. 至少在另一台测试设备或测试浏览器中完成一次恢复验证，再依赖它用于换机或交接。

### 一个可执行的备份节奏

| 时机 | 建议动作 | 为什么 |
| --- | --- | --- |
| 大批量导入前 | 建立恢复点并导出完整备份 | 方便撤回映射错误、重复合并或字段判断错误。 |
| 每个重要节点后 | 导出一份带日期和用途的备份 | 避免把“期末前、评优前、交接前”的状态混在一起。 |
| 换设备前 | 在旧设备导出，在新设备恢复并抽查 | 复制浏览器目录或安装目录不能替代受支持的迁移。 |
| 岗位交接时 | 双方分别保留交接前快照与恢复验证记录 | 让责任边界、附件完整性和后续追溯更清楚。 |

## 网页、离线文件与桌面端的区别

| 使用方式 | 数据通常在哪 | 换设备时正确做法 |
| --- | --- | --- |
| 网页版 | 当前浏览器的本地存储 | 在旧环境导出备份，在新环境恢复。不要依赖浏览器同步。 |
| 离线 HTML | 当前浏览器或便携页面的本地空间 | 把备份与离线文件分开保存；不要只复制 HTML。 |
| 桌面端 | 当前系统用户的数据目录与附件库 | 升级前先导出备份；目标设备安装后再恢复并抽查附件。 |

## 恢复时的安全顺序

1. 先导出目标设备当前数据，作为恢复前快照。
2. 确认备份来源、版本、口令和共享范围。
3. 选择“合并”还是“覆盖”前先看差异说明；不确定时优先在测试环境演练。
4. 恢复完成后抽查学生记录、附件、谈话/任务及资料库，而不只看“恢复成功”提示。
5. 确认无误后再处理旧设备或旧备份。

### “合并”与“覆盖”怎么选

- **合并**适合目标设备已经产生新记录、只希望补进来源记录的情况。恢复后需要抽查同一学生、同一附件或同一业务记录是否出现重复。
- **覆盖**适合明确要回到某一份完整快照的情况。覆盖前先导出目标设备当前数据，因为这一步会改变当前工作区。
- 无论选择哪种方式，附件都应作为恢复后的必查项：随机打开几份记录，检查文件、缩略图和关联学生是否一致。

## 常见误区

- **只复制安装包**：安装包不等于业务数据。
- **只复制表格**：表格可能不包含附件、谈话、任务或资料库索引。
- **把备份当作普通附件转发**：备份可能包含完整学生信息，应按敏感文件处理。
- **在唯一数据上首次测试覆盖恢复**：先做快照，再用脱敏环境演练。

## 版本兼容

发布版本会在 Release 说明中列出可导入的历史格式、schema、加密备份和桌面数据兼容范围。v4.8.5 是当前 schema v11 维护版本，不新增迁移并继续保留旧数据和恢复能力；工作区协议 `schema_version: 8` 继续兼容。正式数据请使用 [v4.8.5 Release](https://github.com/7752777/counselor-desk/releases/tag/v4.8.5) 的实际附件并核对 SHA-256；v4.8.3、v4.8.2、v4.8.1、v4.8.0、v4.7.1、v4.7.0、v4.6.0 及更早版本作为历史兼容版本保留。

### v4.4 / v4.5 的迁移原则

v4.4 使用 schema v8 工作区。v4.5.0 在此基础上新增 `v4_contacts`、`v4_class_schedules`、`v4_activity_participants`、`v4_league_cases`，并扩展导师/班主任、家长关系、居住信息、房东联系方式和历史学号字段。迁移目标是保留内部 ID、附件关联、历史学号、自定义字段和可以读取的历史记录；迁移前会建立恢复点。遇到无法判断的旧字段或冲突记录，系统应提示并保留原始信息供人工判断，而不是静默覆盖。

学生名单默认采用合并更新，源文件缺失不等于删除；覆盖导入是显式模式，必须显示删除数量并先建立恢复点。更正学号只更新当前快照并追加 `student_number_history`，不改变 `student_id`，因此谈话、成绩、资助、就业、党团、活动参与和 AI 建议不会因学号订正而丢失关联。党员流程以 `v4_party_cases` 为主记录，旧 `party` 集合继续镜像；团员发展核心节点和规则版本随记录迁移。

照片、活动照片和业务附件不再把二进制放入 `localStorage`；浏览器使用 IndexedDB 附件仓，Electron 使用加密附件目录，便携包使用附件仓。恢复时除了抽查表格，还必须抽查学生照片、活动/查课查寝附件和附件 ID 回链。容量达到 70% 提示、85% 建议清理、95% 阻止大批量写入；批量附件失败会回滚已写入项。

AI 通知草稿、来源和授权集合随工作区迁移，但 API key、中转令牌和完整通知原文默认不进入备份；通知原文只有在用户明确选择保存时才写入本地资料库。正式兼容范围、加密格式和桌面迁移结果以历史 [v4.7.0 Release](https://github.com/7752777/counselor-desk/releases/tag/v4.7.0) 说明为准；仓库目前为私有，下载和附件需要仓库权限；逐条反馈验证见[老师反馈审计](./upgrade/teacher-feedback-audit-2026-08-18.md)。

### v4.6.0 增量迁移

v4.6.0 的 v8 → v9 迁移只新增 10 个集合和 `v46_schema_version` 标记，不删除或重写 v8 数据。新增集合为住宿五集合、班委角色/考核两集合、家长联系、工作记录草稿和科研课题。浏览器 IndexedDB、Electron SQLite、单文件离线 HTML、备份恢复和手机交换包必须使用同一份集合清单；迁移前仍建立恢复点。

迁移后应抽查：学生稳定 ID、旧学号历史、当前宿舍快照、调宿历史、家长联系、班委考核、科研阶段、待确认工作记录、证书附件 ID 和班级统计。排宿未确认的预览方案不能写入当前住宿；草稿来源发生变化时必须显示过期，不应静默确认。

如果从 v4.6.0 或更早正式版升级，先完成备份，再安装或打开正式 v4.7.0；如果目标环境仍是旧版本，应使用旧版支持的备份和交换格式，不要手工把 v9/v10 集合复制进旧工作区。恢复失败时保留目标设备快照和原备份，停止继续写入后再排查。

### 2026-08-19 收尾维护提示

v4.6.0 发布后的维护级修复已并入 v4.7.0 公开版本。备份/恢复抽查时应额外检查：学生卡片模式、奖惩证书附件 ID、宿舍排宿与调宿作废历史、`v4_photo_queue`、非法日期不会被写入，以及业务记录不会把自身 ID 当成学生 ID。后续维护版本必须重新执行完整测试、构建、公开面和密钥检查，并以新的 Tag/Release 记录兼容事实。

调宿历史不允许通过硬删除破坏轨迹；已经无效的记录使用作废状态保留。奖惩附件删除时会检查是否仍被其他记录引用，只清理孤儿附件并记录审计。恢复时如果发现附件缺失，应先停止覆盖恢复，保留目标快照，再根据附件清单处理。

本次维护候选还修正了以下回读边界：学生照片仍只通过附件 ID 恢复；学生档案补传照片不会把二进制写入学生 JSON；班级分析按记录 `term` 回读并按 `student_id + term + activity_id` 去重；学生时间线会从家校联系、住宿/调宿、班委考核和活动参与关系重新派生。来源已变化的工作记录草稿恢复后仍保持过期状态，不能因为恢复而绕过人工核对。

## v4.7.0 v9 → v10 增量迁移

v4.7.0 仍使用工作区协议 `schema_version: 8`，只把业务 `data_schema_version` 提升到 10。`src/core/v10-migration.js` 会保留 v8/v9 数据、稳定 ID、历史学号、附件引用和自定义字段，只补齐十个新集合以及 `settings.v47_schema_version` / `v47_migrated_at` 元数据。迁移是可重复的：已有数组不会被清空，缺少集合才初始化为空数组。

升级前必须建立恢复点。升级后按以下顺序抽查：学生台账与时间线、查课记录、点名种子和结果、查寝照片/异常、量化积分与规则、竞赛附件、备份恢复、Electron 重启和手机交换包。任何附件缺失或学生 ID 断链都应停止覆盖恢复，保留目标设备快照后再排查。

新增集合清单、浏览器/离线/Electron/备份/交换包接入由 `src/core/cwb-collections.js` 统一派生；不能手工只复制某一个端的集合。v10 属于历史 v4.7.0 兼容基线，定向和完整验证及历史证据见[参考工作台审计](./upgrade/reference-product-feature-and-ui-audit-2026-08-19.md)和[v4.7.0 发布收尾记录](./upgrade/release-v4.7.0.md)。

## v4.8.0 AI 字段兼容

v4.8.0 新增的 `v4_ai_audit.output_redacted` 是既有 AI 审计的可选布尔字段，不新增集合、不改变工作区协议 `schema_version: 8`；旧备份恢复时缺少该字段按 `false` 读取；新备份和交换包必须原样保留它，以及 `request_id`、`draft_id`、`suggestion_id`、`source_ids` 和 `context_scope` 的关联。

模型原始响应不会因为备份而补写入审计；页面返回、草稿和建议使用本地二次脱敏后的文本。`CWB.ai.health()` 是运行时派生报告，不需要迁移，也不应作为恢复成功或 AI 质量的替代证明。v4.8.0 正式 Release 已交付该字段兼容；运行维护仍需按发布收尾记录核对跨端恢复。

## 2026-08-21 来源草稿的跨端保存边界

基础集合（例如任务或谈话）发生变化时，系统可能同时更新 `v4_worklog_drafts` 的来源状态。保存和恢复必须把这次 `custom` 集合变化作为同一工作区保存动作处理；不能只恢复基础集合而把草稿恢复为旧的“有效”状态。来源被删除前已经标记的 `source_state: deleted` 也必须随 v8 工作区、IndexedDB、Electron、便携包和交换包保留。

换机或恢复后，抽查一条来源修改和一条来源删除的草稿：页面内存、`CWB.workspace.getState().custom.v4_worklog_drafts`、备份导出和重新打开后的状态都应一致。若出现草稿从 `changed/deleted` 恢复为 `active/draft`，应停止继续归档，先保留目标设备快照并重新检查恢复链。

## 2026-08-21 AI 审计兼容字段

`v4_ai_audit.provider_id` 是可选的非敏感字段，用于按模型连接隔离每日生成额度。新增记录保留该字段；旧备份缺少它时按 `provider` + `model` 兼容读取，不需要重写历史审计。迁移、备份、恢复和手机交换包应保留它，但不得把 API key、relay 令牌或模型原始响应写入任何包。

`CWBAI.providerReadiness()`、AI 健康卡和当前会话密钥状态均为运行时派生值，不新增集合，也不改变 `schema_version:8` 或业务数据版本。恢复后应重新检查模型配置和当前会话凭据，不能把备份里的 `secret_set` 当作浏览器当前已有密钥；它们不代表历史 Release 中已经保存了当前会话密钥。

## v4.8.0 迁移与备份变化（已发布）

v4.8.0 使用 `v10 -> v11` 增量迁移，工作区协议仍为 `schema_version:8`，另记录 `sync_protocol_version:1`。迁移入口已经内联到网页/离线构建；迁移前必须创建可验证的恢复点，迁移失败时保留旧数据目录、原备份和目标快照，不允许半迁移状态继续写入。物理 IndexedDB 从 v5 增量到 v6，只创建缺失 stores，不删除旧数据。

v4.8.0 已增加桌面主机自动备份到期检查、独立恢复口令、恢复诊断入口和失败回滚契约；Electron/局域网主机按日期或变更阈值运行定时检查，浏览器关闭期间无法后台写文件，页面明确说明这一限制。`CWBV48.createRemoteBackupAdapter()` 已实现 HTTPS/WebDAV 用户自有存储的加密包传输核心：只接受明确标记的加密 `.cwbk`，不传输密钥、明文学生数据或明文附件；完整配置向导和真实服务商互操作仍是发布后抽查项。

v4.8.0 局域网功能采用 Electron 主机服务，不允许客户端共享 SQLite 文件。客户端使用一次性配对码/二维码和证书指纹加入工作区，离线变更进入队列；不同字段自动合并，同字段进入人工冲突收件箱。新设备、冲突、备份运行和恢复操作通过最小元数据审计；手机真实信任、自动发现和长期断网重连仍是发布后限制。

### 2026-08-22 浏览器物理 IndexedDB 升级修复

此前浏览器运行时仍调用 `indexedDB.open('counselor_desk_v4', 5)`，但共享集合已经扩展到 v4.8/v11。已有 v5 数据库不会再次触发升级，因此 `v4_ai_sources`、`v4_sync_devices`、`v4_backup_runs`、`v4_content_pushes` 等 object store 不存在，通知本地预览可能出现“指定 object store 不存在”。

当前运行时把物理 IndexedDB 版本增量到 `6`。该版本只补齐当前 manifest 中缺少的 object store，保留旧记录和旧物理 store；它与工作区 `schema_version:8`、业务 `data_schema_version:11` 分开。回归测试先创建物理版本 5 的旧库，再以当前运行时打开，确认旧学生可读、新 AI/同步/备份/内容集合存在。真实浏览器复验已确认已有工作区重新加载后保存状态为“已保存”，通知本地预览可以生成结果。

这次修复解决的是浏览器旧工作区的集合创建问题；Windows/macOS、手机局域网、WebDAV 和大附件跨端恢复的自动化/正式资产证据见 v4.8.2 发布收尾记录，真实设备抽查仍按发布后限制执行。

### 2026-08-21 迁移和远程备份边界收口

数据目录迁移现在分为“路径校验、复制临时目录、候选仓健康检查、目标激活、原仓回滚”五个阶段。路径校验在规范化之前拒绝空值；候选仓和恢复后的原仓都必须通过加密 payload 健康检查。激活失败返回 `DATA_MIGRATION_ACTIVATION_FAILED` 并恢复原仓；回滚也失败返回 `DATA_MIGRATION_ROLLBACK_FAILED`，此时不保留可写活动仓，用户应停止操作并使用恢复副本或恢复包。

远程备份的 `base_url` 只能是无凭据、无查询参数的 HTTPS 地址；上传/下载端点只能是该基址下的相对路径，`.`、`..`、编码后的目录穿越、绝对 URL、反斜杠和查询片段均拒绝。请求仍禁止重定向、携带浏览器凭据和上传密钥；浏览器关闭期间不能后台执行上传。真实 WebDAV 服务商兼容性仍需发布前实测。

### 2026-08-21 同步失败的恢复规则

局域网同步状态写入失败时，主机必须恢复提交前状态；Electron 业务仓储同时回滚已有记录或删除本批新记录。恢复向导不能通过生成新密钥掩盖旧密钥损坏，不能在回滚失败时继续开放写入。客户端配置错误必须在网络请求前返回稳定错误码，首次连接必须人工核对证书指纹。

本批新增 `tests/v48-p0-hardening.js` 和按风险拆分的 `package.json` 脚本。该测试覆盖状态快照、业务记录、配对限流、HTTPS/凭据/指纹、TLS SAN 和 IPC 诊断；它是代码级证据，不能替代真实设备恢复、Windows/macOS 跨盘迁移或附件大数据量恢复。

## 2026-08-21 浏览器大名单原子载荷回归说明

v4.8.0 浏览器学生大名单导入会把整批替换写入 `records_students` 的 `__cwb_bulk_students__` 原子载荷，再由仓储层解包为逻辑学生记录。该方式避免在大批量写入过程中留下部分可见名单，并保持刷新、恢复和撤销的边界；它不改变导出包中的学生数组格式。

一次全量回归曾发现旧测试直接读取 IndexedDB 原始行数并错误期待 1,200 行，实际原始存储为 1 条载荷记录。测试已改为验证原子载荷存在且仓储 reopen 后恢复 1,200 条逻辑记录；修复后的 `node tests/v8-canonical-idb-browser.js` 已通过。后续迁移、性能和恢复测试不得绕过仓储 API解释底层物理行数。

## v4.9.0 商业凭据与恢复边界

许可证 token、设备令牌、订单访问令牌、管理员密钥和模型 API Key 不是业务集合字段。它们不进入备份包、手机交换包、学生导出、普通诊断日志或工作区迁移；Electron 授权状态由独立 `safeStorage` 文件保存，换机通过授权服务重新激活。业务数据恢复成功不等于商业授权恢复成功。

更新前系统先建立加密恢复点，再下载和校验更新包。安装程序只更新程序目录，工作区数据目录保持原路径；`v4.8.5` 的业务协议仍为 `schema_version:8`、`data_schema_version:11`、`sync_protocol_version:1`。如果签名、哈希、迁移或重启验证失败，保留旧版本、原数据和恢复点，不能通过生成新许可证或新密钥掩盖失败。

浏览器关闭后无法后台写入用户选择的文件目录，单文件离线包不承诺自动升级；浏览器只能保留本地加密快照并提示用户手动导出。Electron/局域网主机可以在进程运行期间按计划创建备份，真实恢复、断网宽限和跨设备重连仍需目标环境验收。

## 2026-08-23 v4.9.0 控制面迁移补充

v4.9.0 不提升工作区 `data_schema_version`，仍保持 `schema_version:8`、`data_schema_version:11` 和 `sync_protocol_version:1`；v4.8.5 工作区可以直接打开。商业许可证、设备注册、订单取件令牌和更新安装状态不是工作区业务集合，不随学生数据迁移。Electron 许可证状态留在系统 `safeStorage` 文件，更新状态留在 `vault/update-install-state.json`；二者不能通过普通业务备份复制到新设备。

授权服务自己的 PostgreSQL schema 只做增量变更：订单表增加可选的 `access_token_expires_at`，旧订单按创建时间兼容计算，不回写学生工作区、不删除订单历史。数据库迁移失败时保留当前授权库；业务工作区恢复失败时仍使用已有恢复点回滚，不能通过重新生成许可证或密钥掩盖失败。

更新恢复流程的顺序固定为：创建加密工作区恢复点 → 下载临时包 → 验证清单原文签名、SHA-256 和平台签名 → 用户确认安装 → 重启后验证目标版本及 SQLite/WAL/附件健康 → 成功提交或保留失败目录并回滚。浏览器/离线 HTML 没有卸载式自动升级能力，客户页订单取件令牌也不进入工作区备份。

本轮新增的授权服务/客户页契约测试覆盖令牌过期、客户页交互、HTML 转义、旧浏览器随机 ID 回退、精确 CORS 和错误码映射；这些是代码级证据，不替代生产 PostgreSQL/KMS、支付/邮件、TLS/CDN、Windows/macOS 实机、公证和跨重启恢复演练。
