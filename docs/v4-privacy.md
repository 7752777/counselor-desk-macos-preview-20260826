# 隐私与安全边界

## v4.9.0 同步和敏感数据边界

许可证令牌、设备凭据和模型 API Key 与学生业务数据严格分离。Electron 只把许可证状态写入 `safeStorage` 保护的 `vault/license-state.bin`；渲染层公开状态会移除激活码和签名载荷，DOM 事件、日志、业务审计、备份、交换包和导出均不得包含令牌。未激活时不会发送 AI 请求；已激活也只允许生成建议/草稿，不能自动改变学生事实或高风险结论。商业 relay、KMS、支付和更新 CDN 是独立部署边界。

前瞻长期通用兑换码属于授权服务的活动凭据，不属于学生业务数据。服务端只保存其哈希、活动状态和兑换审计，不保存普通日志中的明文；客户端只在用户主动粘贴并联网兑换时提交一次。活动码可以被多位前瞻体验用户使用，但每个工作区兑换后拥有独立许可证。因为明文一旦被转发就可能继续使用，维护者应把它当作可撤销的前瞻体验权宜方案，正式收费用户仍应使用独立许可证。

v4.9.0 的匿名运行指标是独立的可选通道，默认关闭。用户主动开启后，只允许发送版本、平台、有限的事件名称和耗时/数量等白名单属性；安装标识在授权服务端用部署侧盐值 HMAC 后才保存。指标链路不接收学生姓名、学号、稳定 ID、记录 ID、附件、地址、联系方式、心理/资助/纪律内容、模型请求内容、模型输入输出或 API Key。关闭同意后不再发送新事件，服务端不提供通过指标反推出学生业务的接口。

> v4.8.2 的领导统计、班级分析和导出默认只允许必要的数值聚合，不输出姓名、学号、联系方式、地址或心理详情。住宿、家长联系、班委考核、科研、证书、查课查寝、竞赛、内容推送和工作记录草稿继续遵循“最小化、脱敏、授权、草稿、人工确认”的边界；本轮同步状态和业务仓储失败回滚不扩大数据出站范围；逐条实现事实见[客户反馈审计](./upgrade/customer-feedback-audit-2026-08-21.md)、[局域网同步与存储记录](./upgrade/lan-sync-and-storage-v4.8.0.md)和[参考工作台审计](./upgrade/reference-product-feature-and-ui-audit-2026-08-19.md)。

> 本轮 AI 安全收口另有一条强制规则：即使当前请求授权身份信息，内部稳定 `student_id`、记录 `id/record_id`、附件 ID、审计 ID、来源指纹和请求索引也不会出站；证书识别的授权、模型请求、草稿和确认审计使用同一 `request_id`。只有学号快照的直接上下文会先解析稳定 `student_id` 做范围校验；本地来源目录仍可在本机保存稳定回链和指纹，用于防止资料变化后继续转化，不代表这些索引会发送给模型。provider、relay 和网页来源统一拒绝 IPv4-mapped IPv6、保留网段、文档网段和其他特殊地址。v4.8.5 另把完整 AI 定向套件纳入主发布测试，测试门禁仍不等于真实模型质量或学校合规评估。逐项状态见[2026-08-20 AI 全面收口审计](./upgrade/ai-comprehensive-audit-2026-08-20.md)。

> v4.8.0 继续执行四条运行时边界：直连 provider 的响应在 JSON 解析前按 UTF-8 字节限制，非法 JSON 不保存原文；请求取消即使发生在服务端返回之后，也不会落库为成功草稿或建议；图片请求必须使用明确声明支持视觉的 provider，Anthropic 图片消息会转换为官方 base64 结构；公共消息入口会移除未知结构字段。建议质量反馈只保存“有帮助 / 需要修改 / 不适用”枚举和审计关联，不保存老师额外输入的原文，也不改变学生事实。

v4.8.5 延续首页、排版、筛选、上下文面板和移动导航的呈现收口，补充单文件离线资源自包含验收，不扩大 AI 默认上下文，不改变敏感字段授权、访问锁、审计或附件仓边界。相关设计过程和历史验收见[UI 收口审计](./upgrade/ui-redesign-closeout-audit-2026-08-19.md)。

辅导员工作台的设计方向是本地优先：项目不要求创建中心化账号，也不以项目服务器收集学生业务数据。这个方向不能替代学校的数据制度、终端管理和专业伦理要求。

## 项目不做什么

- 不提供项目自建的云端学生数据库或统一账号体系。
- 不进行人脸识别、生物特征分析或自动化心理诊断。
- 不替代学校正式审批、心理专业评估、危机处置、资助认定、纪律处理或党团审批。

## 你仍需要负责什么

- 只在学校允许、自己可控的设备和账户上处理真实学生数据。
- 按最小必要原则记录、导出和共享信息。
- 对心理、健康、家庭、纪律、资助、联系方式和党团材料设置更严格的保管与交流范围。
- 为浏览器数据、桌面数据目录和备份文件建立定期备份与访问控制。
- 在展示、培训、Issue、截图、示例和测试中只使用虚构或脱敏数据。

## 本地并不等于自动加密

浏览器本地存储、桌面数据目录和导出文件都有设备遗失、恶意软件、共享账户、同步工具或误发的风险。重点学生界面锁明确标注为“仅防误看，不是加密”；清除锁只清除界面限制并记录审计，不代表恢复或保护数据。界面锁、备份口令和操作提示只能提供部分保护，不能替代磁盘加密、系统账户、终端管理和学校制度。Electron 的附件仓和备份可以使用系统安全存储/加密，但不等于浏览器工作区已经实现数据库级加密。

## 处理敏感信息时的实践清单

| 场景 | 建议 |
| --- | --- |
| 截图与培训 | 使用虚构学生、模糊或移除学号、联系方式、照片和家庭信息。 |
| 导出表格 | 只选必要字段；发送前再次确认接收对象、用途和保存期限。 |
| 备份交接 | 使用学校认可的受控渠道；单独传递口令，不在同一群聊或邮件正文中附带。 |

| 问题反馈 | 提供最小化、脱敏、可复现的信息；不要上传数据库、备份包或完整日志。 |

## v4.5.0 / v4.6.0 / v4.7.0 新增本地数据边界

- `v4_contacts` 是个人通讯备忘录，默认不与学生档案关联、不进入平台联动，也不自动发送给 AI。
- `v4_class_schedules` 只记录所带班级的课程安排；课表导出仍需按接收范围最小化。
- 活动照片、查课查寝照片和业务附件统一写入 IndexedDB、Electron 附件仓或便携附件仓，业务记录只保存附件 ID。容量检查会在 70%/85%/95% 分级提示或阻止大写入。
- 学生照片、家长联系方式、家庭地址、居住类型、房东电话和心理/资助/纪律信息均按敏感字段处理，导出预览默认要求人工确认。
- 访问审计记录敏感档案查看、导出、备份、重点学生锁和附件操作；审计保存在本机，不上传云端。
- v4.6.0 的宿舍安排、调宿、家长联系、班委考核、科研项目和工作记录草稿只保存在当前工作区，默认不上传；个人通讯录 `v4_contacts` 与家长联系 `v4_family_contacts` 分开，不能因联系人相似而自动关联。
- 宿舍方案、班级分析和 AI 输出均为预览、派生结果或草稿。宿舍必须人工确认后才更新学生快照；班级分析只给聚合数，敏感指标不显示个人明细；AI 不决定床位、评价等级、奖惩结论或科研审批状态。
- 证书和走访照片等二进制只进入附件仓，业务记录只保存附件 ID。删除附件需要二次确认和审计；附件导出、备份和恢复都属于敏感数据处理。
- 手工录入奖惩时，证书/证明材料沿用同一附件仓；删除奖惩记录只清理不再被其他记录引用的附件，避免共享引用变成断链。宿舍调宿历史使用作废标记，不提供无审计的硬删除。
- 工作记录草稿保存来源集合、来源 ID、来源哈希和人工状态；业务记录变化后草稿标记过期，避免把旧摘要误当成新事实。
- 学生画像和家校联系列表默认只显示手机号脱敏值；完整号码查看前必须启用工作台访问锁并完成验证，同时写入访问审计。没有访问锁时不提供“直接解除限制查看”的后门。
- 班级分析默认只显示班级/学期聚合数量；个人姓名、学号、重点关注和学业预警明细通过单独的访问锁动作打开，指标下钻同样受控。
- v4.7.0 的查课、点名、查寝、量化考评、就业防骗、竞赛资源和工具链接默认保存在当前工作区；外部 URL 只有在用户明确触发后才校验和打开，不做后台抓取或全网爬取。
- v4.7.0 的 `v10` 集合统一进入浏览器 IndexedDB、离线 HTML、Electron、备份恢复和手机交换包，但跨端一致接入不等于云端同步；交换和导出仍是一次新的敏感数据处理，需要在操作前确认范围。
- 通知双栏、右侧上下文区和 AI 页面入口不会自动扩大模型上下文。当前学生、班级、课表、查寝、量化或竞赛数据只有在明确触发对应 AI 用途并完成必要授权后才进入请求；结果必须保留来源、审计和人工确认状态。

## 收尾维护中的数据完整性规则

- 业务记录必须显式保存 `student_id` 才能建立学生关联；记录自身 `id` 不得被当作学生 ID。学号只能作为兼容快照。
- 排宿确认不是对旧预览的盲写入。确认时会重新检查当前活动住宿、床位、房间和楼栋状态；数据发生变化时应拒绝写入并重新生成方案。
- 日期输入按真实日历校验，不接受会被自动归一化的不存在日期。错误日期应在输入或生成阶段被拒绝，而不是写入后再修正。
- 浏览器离线启动、IndexedDB、Electron 和便携包必须共享同一集合清单；`v4_photo_queue` 等附件相关集合缺失时不能静默启动为“空集合”。
- 工作记录草稿在来源哈希变化或来源删除后自动进入过期状态；必须重新打开原始记录，编辑草稿并明确勾选重新核对，来源已删除的草稿不可归档。
- 证书附件删除前要检查同一集合的其他引用，只删除确认不再引用的孤儿附件；共享附件不能因删除一条奖惩记录而断链。

## AI 通知边界

通知识别只在老师主动粘贴文字或选择文本文件后运行，不读取钉钉、学校系统、剪贴板历史或浏览器通知。默认仅保存标题、摘要、截止时间、待办、证据片段和原文哈希；完整原文只有在确认时明确选择保存才进入本地资料库。AI 结果先是草稿，确认后仍由老师分别选择转任务或工作留痕，不自动改变学生事实、党团节点、心理结论、资助、纪律或预警。

## AI 请求的生命周期

- 默认请求只携带脱敏后的业务上下文；敏感分类或字段必须在当前请求前明确授权，授权完成、取消或失败后失效。
- “暂不授权”只关闭确认流程，不会向模型发送请求；页面会清除待确认的请求状态。刷新后若仍显示未完成状态，使用“取消请求”即可清理并重新开始。
- AI 输出只创建建议、草稿或待确认记录。建议转为任务、谈话或工作留痕前仍须人工审核，心理、预警、纪律、资助、奖惩和学生事实不会自动改写。
- 请求审计只保存用途、模型、范围、授权状态、来源 ID、敏感分类/字段、建议/草稿关联、耗时、截断状态和安全错误码；API 密钥、中转令牌、完整请求、完整响应和请求文本不进入业务备份、重试状态、日志或导出包。
- 生成审计会回填 `suggestion_id`、`draft_id`、`source_ids` 和 `context_scope`；确认审计通过 `parent_audit_id` 回到生成审计。业务记录只保存 AI 元数据，不把模型输出当作学生事实。
- AI 请求的临时文本、请求内容和完整来源记录不会写入持久化 `ui_state`；明确保存的 AI 草稿仍属于敏感本地数据，应按备份和导出边界管理。
- “测试连接”只发送固定的最小测试消息，不带当前学生、班级、事项或业务记录，只保存成功/失败、模型、耗时和安全错误码。
- 政策智库和就业资源中的外链也经过统一地址校验，只允许绝对 `http`/`https` 地址，拒绝危险协议、相对地址、带凭据地址和异常长度；地址未通过校验时不会在页面生成可点击链接。该校验不等同于对目标网站内容的可信认证，业务人员仍需核验来源和页面内容。

## 2026-08-20 AI 收口规则

- `identity` 授权不是全库姓名/学号授权：出站允许值只来自当前学生、当前班级或当前上下文实际关联学生；内部 `student_id` 始终不出站。
- 每日额度只统计真实模型生成审计（`action: generate`），授权、反馈、建议转化和确认操作不消耗模型生成额度。
- 建议进入任务、谈话或工作留痕前必须同时存在已采纳状态、人工确认时间和确认方式；缺任一项都只能停留在建议状态。
- 浏览器和 relay 两端都会清理公开来源 URL 中的令牌、会话、学生标识等敏感查询参数并删除片段；来源记录只保留清理后的地址。
- 连接测试不携带业务上下文；停用模型直接拒绝，取消请求记录为 `cancelled`，不生成草稿或建议。

以上规则有 `tests/cwb-ai-context.js`、`tests/cwb-ai-source.js`、`tests/cwb-ai-workflow.js`、`tests/ai-contract.js` 和 `tests/ai-governance-boundaries.js` 回归覆盖。

重点学生锁仍是防误看，不是数据库级加密。真正加密、忘记密码不可恢复、跨端密钥管理和加密备份必须单独完成威胁建模与恢复测试；历史暴露过的外部 API key 必须在服务商后台撤销和轮换。

## 记录级 AI 入口的隐私边界（2026-08-20）

课表、当前住宿和已保存点名结果现在可以从具体记录触发 AI，但“绑定记录”只用于本机建立上下文和来源回链，不代表内部记录 ID、稳定 `student_id` 或学号快照会发送给模型。点名结果中的候选和选中学生 ID 仍属于本地敏感索引，出站时清理。

课表 AI 只提供安排和工作行动建议；住宿 AI 只解释容量、床位、批次和调宿冲突；点名 AI 只整理已保存且人工复核的结果为留痕草稿。三类动作均不得自动写入学生事实、住宿快照、正式考勤或其他专业结论。入口、用途和未完成边界详见[AI 实现逐项对账](./upgrade/ai-implementation-reconciliation-2026-08-20.md)。

AI 用途选择也遵循最小权限：工作台直接展示 canonical `warning_assist` 和 `certificate_recognition`，历史别名只做兼容归一化；未登记用途返回 `AI_PURPOSE_INVALID` 并阻止出站请求，不会借用其他用途的 provider 授权、额度或上下文规则。

## 2026-08-20 AI 输出二次脱敏

AI 的脱敏不只发生在请求发出前。模型返回文本会在页面显示、写入 `v4_ai_drafts` 或写入 `v4_ai_suggestions` 前再次清理；未授权姓名、学号、手机号和邮箱，以及 `student_id`、业务记录 ID、附件/审计/请求索引不会因模型回显进入本地结果。当前范围的身份/联系方式授权只允许当前请求需要的字段，内部关联 ID 永远不放行。

生成审计的 `output_redacted` 只记录是否发生二次清理，不保存模型原文。AI 工作台的 `CWB.ai.health()` 是只读运行状态报告，不是加密证明，也不是模型质量证明；看到“运行链完整”仍需人工核对建议、来源和业务事实。

## 2026-08-21 保存失败与来源草稿边界

保存失败时，工作台会保留表单、确认框和待重试状态；“重试”不会绕过访问锁、来源复核或人工确认。基础记录修改/删除造成的 `v4_worklog_drafts` 状态变化会与 `custom` 集合一起写入工作区，避免恢复后把已变化或已删除来源误显示为有效草稿。草稿不是正式工作事实，来源状态异常时不得继续归档。

## 2026-08-21 模型可用性与密钥状态

AI 生成按钮会在出站前检查用途授权、视觉能力、当前会话凭据和该模型自己的额度。`secret_set` 只表示模型曾配置过密钥，不是密钥内容，也不代表普通浏览器当前会话仍可调用；密钥只留在 Electron 安全存储或浏览器当前会话。页面禁用按钮是可用性提示，公共运行入口和请求前仍会二次拒绝。

`v4_ai_audit.provider_id` 只用于模型连接级审计和额度隔离，不包含任何凭据。额度只统计成功生成；连接测试、失败、取消和本地通知预览不扣额度。readiness 是运行时派生状态，不进入备份或交换包，旧审计缺少 provider ID 时按连接器和模型名兼容读取。完整行为见[AI 模型可用性审计](./upgrade/ai-provider-readiness-audit-2026-08-21.md)。

## v4.8.5 同步和敏感数据边界

v4.8.5 不扩大 AI 默认上下文、不改变敏感字段授权、访问锁、审计或附件仓边界。学生台账 AI 操作只是固定到操作单元格，移动端分页和资料列表修复只改变可见布局；本版增加单文件离线资源自包含和本地 HTTPS/WebDAV 传输测试，但不把传输测试当作真实服务商合规证明。所有 AI 结果仍只生成建议、草稿或待确认留痕，不自动修改学生事实或高风险业务。

## v4.8.2 同步和敏感数据边界（历史维护）

v4.8.2 沿用 v4.8.0/v4.8.1 的局域网配对、设备撤销、冲突收件箱、加密附件和端到端加密备份边界。本次维护明确同步持久化失败只回滚本地状态，不静默丢弃队列或推进游标；证书图片会发送给已选视觉模型，且仅单次、单附件授权；恢复包口令至少 12 位，遗失口令仍没有后门解锁。以上提示和回滚只改变用户确认前的可见信息及失败行为，不扩大 AI 默认上下文，也不改变敏感字段授权。

## v4.8.0 同步和敏感数据边界（历史发布）

v4.8.0 局域网主机只接受明确配对的设备，并默认限制在同一局域网；配对、同步、设备撤销、冲突解决和附件传输通过最小元数据写入本地审计。客户端离线队列由同步服务管理，主机恢复后再提交；不能把 SQLite 文件放进共享文件夹供多个端直接打开。手机真实 HTTPS 信任、自动发现和长期断网重连属于发布后实机抽查，不被自动化契约测试冒充为已验收。

云端首期只允许用户明确触发上传端到端加密备份包。适配器要求 HTTPS、禁止 URL 内嵌账号密码、禁止跟随重定向、限制请求大小和超时，并使用 `credentials:omit`；密钥、恢复口令、API key、relay 令牌、完整 AI 请求、完整响应、心理原音频和明文附件不能进入远程存储。独立恢复口令遗失时不提供解除加密的后门。真实 WebDAV 服务商兼容性属于 v4.8.0 发布后的维护抽查。

心理语音页面每次重新授权，默认不保存音频；AI 返回的转写只作为二次脱敏草稿，人工确认后才进入心理工作记录。群体心理画像只能输出满足最小人数阈值的脱敏聚合，不进行诊断或危机认定。录音权限、长音频稳定性和真实模型质量仍需设备验收。

### v4.8.0 发布后安全边界

截至 2026-08-22，局域网主机 HTTPS、一次性配对、设备撤销、客户端连接/拉取/推送/离线队列、冲突收件箱、主机真实 SQLite 回写、最小同步审计、加密附件上传/下载、备份运行记录、只传输加密包的 HTTPS/WebDAV 适配器核心、远程备份配置/测试连接/上传/下载预览恢复/删除页面、学生批量维护页面、心理真实录音转写页面和群体聚合页面已随 v4.8.0 Release 交付并通过定向测试。手机真实 HTTPS 信任/自动发现、真实 WebDAV 服务商互操作、真实设备逐集合恢复、长期断网重连和 Windows/macOS 实机回滚仍属于发布后维护抽查，详见[客户反馈逐项审计](./upgrade/customer-feedback-audit-2026-08-21.md)。

同步审计只保存必要的操作元数据：集合、记录 ID、设备 ID、操作 ID、版本、冲突字段名、附件大小/哈希和结果状态。不会把令牌、字段补丁值、学生明文或附件内容写入普通审计。主机正式附件和断点上传临时分块均使用 AES-256-GCM 加密落盘；授权下载后才返回明文到当前会话。主机和客户端仍必须在可信设备与网络上使用，局域网不是安全边界。

内容推送的 `workspace_admin`、`content_editor`、`teacher`、`viewer` 是本地工作区策略标签，不是账号认证。页面列表、已读和普通角色导出都按当前工作区的学院/年级/班级上下文过滤；普通角色的内容包只包含本人已读回执，管理员才可按权限导出全量回执。内容推送不承载学生明细，也不因局域网同步而扩大敏感数据范围。角色变更、发布、导入、导出、已读和撤回只写最小审计元数据。

工作留痕导出可以包含来源集合、来源记录 ID、来源标题、来源状态、来源更新时间和顶层 `provenance`。这些字段用于人工回查，不等于来源认证；来源已变化或已删除时必须重新核对，不能把导出包中的旧摘要继续当作权威事实。

## 2026-08-21 数据目录与远程端点安全补充

数据目录取消、空路径和工作区内路径不会被当成有效迁移目标；迁移切换失败时保留原目录和恢复副本，回滚失败则停止写入，不自动生成新密钥覆盖旧仓。远程备份端点在请求发出前只允许同源相对路径，防止把备份请求引向其他站点或基址目录之外；端点校验错误不应被界面显示成普通网络故障。

局域网配对弹窗可显示二维码并复制公开连接所需的地址、一次性配对 ID、配对码和证书指纹，但不会显示或复制主机管理令牌。当前没有自动发现，扫码/手动输入和主机确认是有意保留的授权步骤。配对码、恢复口令、API key、Bearer/Basic 凭据和心理原音频不得进入日志、普通备份、交换包或内容推送。

## v4.8.0 同步失败回滚与诊断（2026-08-21）

同步主机的状态快照和业务记录必须一起提交。状态文件写入失败时，主机恢复内存快照；Electron 适配器再恢复已有记录或删除本批新记录。回滚失败不得生成新密钥覆盖旧密钥，也不得继续把工作区显示为健康可写状态。`SYNC_STATE_PERSIST_FAILED`、`REPOSITORY_DECRYPT_FAILED`、`VAULT_KEY_DECRYPT_FAILED` 等错误码只携带处理建议，不在普通日志中写入密钥、令牌、字段值或附件内容。

同步成功审计只在状态与业务记录都提交后写入；失败操作的审计队列会丢弃，不会留下可被误解为真实事实的成功记录。

客户端只允许 HTTPS，并要求首次人工核对证书指纹。地址中的账号、密码、查询参数和片段被拒绝；校验错误在发起网络请求前返回，不会伪装成连接失败。配对码是短期 8 位数字，错误尝试达到 5 次即限流；配对码和证书指纹不是设备令牌，不能发到公开群组。

局域网配对确认后，客户端通过请求 ID和设备 ID一次性领取设备令牌；令牌只存在当前会话和主机短期交付内存，不写入 `ui_state`、备份、交换包或普通审计。主机健康接口、设备列表和认证返回值只提供公开设备元数据，不返回 `token_hash`。设备暂停会立即阻断同步、冲突和附件接口，恢复后继续使用原令牌，撤销后必须重新配对。

客户端自动同步只提交业务变更和附件 ID，不把令牌、完整请求、字段补丁值或附件明文写入普通日志。连接失败保留本地队列并显示错误码；浏览器关闭期间仍不能执行后台文件备份或同步。桌面二维码已随 v4.8.0 交付，但自动发现和真实手机证书信任尚未验收，不能把局域网连接理解为绝对安全边界。

### 二维码隐私边界的最新补充

桌面端二维码已随 v4.8.0 交付，但二维码不是授权令牌，也不是安全边界。载荷白名单只允许协议版本、HTTPS 地址、工作区 ID、一次性配对 ID、8 位配对码、证书指纹和过期时间；不会包含主机管理令牌、设备令牌、`token_hash`、主密钥、API key、学生字段、业务记录或附件内容。二维码过期后必须重新生成，扫码后仍需人工核对证书指纹和主机确认。真实手机扫码、自签名证书信任和自动发现仍待发布后验收。

## 2026-08-22 当前安全事实

证书图片入口已统一为“附件逐次授权 -> 视觉模型 -> 草稿 -> 人工确认”的单一路径，旧的无授权重复入口已删除。建议批量审阅的状态和审计也必须原子保存；保存失败不应清空选择或留下成功状态。真实数据库级加密、历史密钥轮换、真实设备和 WebDAV 互操作仍是 v4.8.1 的发布后限制。

重点学生 PIN 锁仍明确为“仅防误看，不是数据库级加密”；私有 GitHub 仓库也不等于本地终端、SQLite、附件仓或备份已加密。AI 保存链路已补充授权、审计、来源和建议的失败回滚；兼容离线队列在无 IndexedDB 时明确不宣称数据库级加密。完整安全边界、剩余风险和发布阻断项见[当前收口总账](./upgrade/closeout-status-2026-08-22.md)。

审计写入失败现在分为两类：高风险动作（敏感查看、导入提交、备份恢复、附件操作、党团节点、文件删除、设备/内容权限等）返回 `AUDIT_WRITE_FAILED` 并保留可诊断的动作名；普通动作返回 `ok:false` 和 `AUDIT_WRITE_DEFERRED`，不再静默返回 `null`。调用方可使用 `CWB.audit.required()` 强制要求审计成功。审计错误不会携带密钥、令牌、字段补丁值或附件明文。

## v4.9.0 商业授权服务边界

商业授权服务与学生工作区分离。授权服务只处理订单、许可证、设备、支付事件摘要、邮件投递状态、更新清单和管理员审计，不接收学生台账、谈话内容、业务附件、模型 API Key、模型输入文本或完整 AI 响应。激活请求只带许可证、工作区绑定标识、设备标识和必要版本信息；业务备份、交换包、导出和普通日志不携带许可证 token。

许可证状态在 Electron 使用系统 `safeStorage` 独立保存；网页和单文件伴侣的浏览器存储不提供同等硬件安全边界。许可证丢失或撤销不会删除学生数据，也没有通过业务恢复包绕过重新激活的后门。AI 档位只解锁本地 AI 工作流，模型服务的密钥、费用和第三方数据处理责任由客户自行承担。

订单交付的访问令牌与许可证 token 分离。授权服务只把订单访问令牌的哈希和过期时间写入授权数据库，新订单默认 7 天有效；客户页在当前会话中使用令牌查询订单和下载 `.cwb-license`，过期后返回 `ORDER_ACCESS_EXPIRED`。普通订单摘要、学生备份、交换包和导出均不携带激活码。下载接口使用 `Cache-Control: no-store`，服务端审计只保留订单/许可证编号和动作。生产授权服务只接受精确配置的 HTTPS CORS 来源，不允许通配符。

更新状态文件位于 Electron 用户数据目录的 `vault/update-install-state.json`，只记录目标版本、阶段、恢复点元数据和错误码。它不包含学生字段、附件正文、许可证 token、设备令牌或模型 API Key。更新失败时保留当前失败目录和恢复点；许可证丢失不能从业务备份恢复授权，需走授权服务重新激活。
